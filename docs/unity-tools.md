# Unity agent tools

Per-tool contracts for the agent inspection harness (`agent-tools`) and the vendor→owned avatar kit (`avatar-tools`) — the static-method tools called via `execute_code`. The cross-cutting conventions (handle style, the namespace/assembly split, the `whatIf`/`preflight` preview grammar) and the MCP/sharp-edges operating knowledge are `unity.md`'s; controller and clip tooling is `animator.md`'s. Per `tool-design.md` §What the call already teaches, no entry below describes what a door returns — drive it and read the output.

## Inspection & reporting (agent-tools)

Shipped as `com.ryan6vrc.agent-tools` (from `vrc-unity-tools`, a local `file:` ref); also home of the shared reporting conventions (`RunLogFormat`, the `[AgentTool]` marker). Two output dirs, declared once each: `RunLogDir` (`Assets/Agent/RunLogs/`, verdict records) and `SnapshotDir` (`Assets/Agent/Snapshots/`, read-only captures).

**Invocation.** `execute_code` compiles your snippet as a **method body**, so a `using` directive cannot sit at the top (the proxy refuses it) — **fully-qualify each call**: `Ryan6Vrc.AgentTools.Editor.<Tool>.<Method>(…)` here, `Ryan6Vrc.AvatarTools.Editor.<Tool>.<Method>(…)` in §Avatar tools. The type namespace is `Ryan6Vrc` and the `.Editor` suffix is required — both are the recurring stumble. Each door below carries one literal call pinning its entry-point *name* (`tools/sync_tool_inventory.py` checks every door has one and names a real method); **arguments and defaults are illustrative, so read the signature when the argument list matters.**

`Ryan6Vrc.AgentTools.Editor.AgentInspector.Run("Root/Child/Path", includeChildren, followAssets)` snapshots a hierarchy path to JSON under `SnapshotDir`, walking any component generically via `SerializedObject`. Every objectReference carries `guid`/`fileId` unconditionally, so each ref is edit-addressable. `followAssets` additionally inlines a recursive dump of each **ScriptableObject-asset** ref — a `VRCExpressionsMenu` `subMenu` chain or `VRCExpressionParameters` expands to the whole tree in one snapshot; non-SO assets (meshes, clips, controllers) get identity only, so there is no overlap with `ReportController`/`ReportClip`. A whole-hierarchy walk of a complex vendor avatar runs past the agent read cap; the artifact is never truncated to get there, only the summary. It dumps raw values — decoding them stays yours.

`Ryan6Vrc.AgentTools.Editor.ReportGimmick.Run(rootPath)` sits opposite `AgentInspector`: where that dumps one object's raw fields, this interprets a whole gimmick subtree into a compact digest and is complete by construction, a tier-2 census naming every component no table interpreted. Reach for it to reason about a gimmick's topology; drop to `AgentInspector.Run(<host path>)` for a component's nested structs, arrays, or followed assets. **This is also why you let the tool read the avatar rather than hand-grepping prefab YAML:** Modular Avatar components serialize by script **GUID** (MergeArmature is `2df373bf…`), never the string `MergeArmature`/`nadena`, so a name grep of the YAML finds nothing. Its physbone chain-subtree census is **reported, not judged, and deliberately not a dead-chain verdict** — a pre-bake bone that will name-merge onto a base bone reads zero skinned because the base mesh skins the *base* transform, and a chain whose consumer sits outside it reads all-zero while load-bearing. `Ryan6Vrc.AgentTools.Editor.ReportGimmick.ScanConstraintLengths(root)` is the constraint-overflow scan through its own door.

`Ryan6Vrc.AgentTools.Editor.ReportPrefab.Run(handle, all)` reads a prefab instance or a `.prefab` variant as the **chain** it is, one block per level up to the Model or Regular prefab it bottoms out on: what each level adds, removes, and overrides against its parent, with the overrides tiered so a framework stamp is counted rather than read. Every other door here sees the flattened result. Hand it an **outermost** scene instance root or the asset path itself — the five `PrefabUtility` lists read straight off a loaded asset, so an asset needs no scene and no `LoadPrefabContents`. Rows are the `authored` tier unless `all:true`; every tier is counted either way.

**`churn` is an allowlist, so a newer stamp reads as authoring.** It is `PrefabChurn` (one file, also holding `SceneDivergence`'s narrower scene-stamp set) plus one rule for Modular Avatar's load-time `targetObject` stamp, so a family newer than the list lands in `authored` and is only recognizable there by its unfamiliar name.

`Ryan6Vrc.AgentTools.Editor.ReportPrefab.Dependents(assetPath)` is the reverse read: every prefab and scene under `Assets/` that **contains** the asset — a `variant` of it, a prefab that `nests` an instance, a `scene` placing it — walked transitively through variants and nesters, so a variant of a nester is found. A prefab that merely `references` it (a constraint source, a shared mesh) is listed and not walked. `Packages/` is not scanned.

`Ryan6Vrc.AgentTools.Editor.ReportComposition.Run(avatarRoot, bake=false, paramFilter=null)` answers the one question no other door crosses the seams for: **where behaviour comes from on a composed avatar** — per parameter, the declaration, every writer and every reader, per merged surface (descriptor playable layers, each MA MergeAnimator, each VRCFury FullController), plus the merge-surface table and the authored menu-control union. It earns its place because deciding whether one toggle exists routinely takes five artifacts, each reading perfectly consistent on its own with the wrong answer: `ReportGimmick` reports a declared `parameter` field and by contract never traces it into an animator, `ReportController` sees one controller, `CheckAvatar` gates reference integrity. Scene door, read-only, artifact to `SnapshotDir`; `paramFilter` narrows every table so chasing one parameter costs one row rather than the whole avatar.

Plain mode is the **authored** census; `bake:true` measures composed truth by building a throwaway clone through the VRC SDK preprocess chain and diffing it against that census. Three things the output cannot tell you about itself. **Attribution is inference** — a prefixed name is recovered by suffix plus owning surface, and no build-time naming grammar is pinned anywhere. The sync columns are **authored in both modes**, so no artifact from this door is evidence about sync state (`runtime.md` §VRCFury build-time reshaping owns why). And the built texture-memory column **overstates an unlocked Poiyomi upload**, because VRCFury inhibits during a bake the material lockdown that strips texture entries bound to disabled shader features. Its geometry and texture sections count every renderer under the root active or not, because the build merges toggled-off renderers into an always-active mesh and an active-only read would report that merge as a deletion.

**Bake mode is two-phase.** The preprocess chain outruns the MCP transport window, so `Run(…, bake:true)` writes its artifact path to disk *before* starting work and returns `PENDING`; `Ryan6Vrc.AgentTools.Editor.ReportComposition.Verify(avatarRoot)` re-reads the verdict. A transport timeout therefore loses nothing **and the call must not be re-issued** — a duplicate while one is in flight returns the same path rather than starting a second build. It builds its own clone and never consults a leftover under `Packages/com.vrcfury.temp/` (those reflect the VRCFury version that made them). A bake failure publishes **no parameter table at all** rather than falling back to authored-only output, because authored rows under a heading promising composed truth is the misread the door exists to prevent. Bake builds an **edit-mode** clone, so `PlayGate`'s one-active-avatar ritual does not apply. Default off: exactness is opt-in.

`Ryan6Vrc.AgentTools.Editor.ReportConsole.Run(types, filterText, count, includeStackTrace, stripBenign, collapseDuplicates)` reads the Editor console — every line of every entry, `filterText` matching body and callstack rather than just the header. Output is inline rather than an artifact, since the message text is itself what you came for. It writes nothing to the console it reads, so it never pollutes its own next read.

**`stripBenign` defaults on, and you usually want it there.** Four families are known noise, and Unity types several as genuine **errors**, so reading the entry's type will not separate them from real ones however faithfully you do it — an unfiltered `types:"error"` read during a build buries the diagnosis you ran it to find. An entry kept because it matched `filterText` is exempt, so filtering *for* noise by name still returns it. Pass `stripBenign: false` for the raw buffer. `collapseDuplicates` keeps the **last** occurrence, because `count` clamps from the newest end — so an oldest representative can be clamped away, erasing the recurrence from the read taken to see it. `count` bounds *rows*, and the window can reach further back than that many entries. A `filterText` match is exempt here too, which is what keeps `emulator.md`'s tagged-probe idiom whole: there the identical repeats *are* the series.

**A family keys on the source it identifies, never the library it came through** — NDMF, MA and VRCFury all Harmony-patch at startup, so a `HarmonyLib` predicate would strip a failed VRCFury patch by default. When entries hidden from this read are themselves needed, `Application.consoleLogPath` (Editor.log) is the unfiltered text of record, process-wide and unstructured. Clearing has no door here and `UnityEditor.LogEntries` is internal, so the `execute_code` form is reflective: `typeof(UnityEditor.Editor).Assembly.GetType("UnityEditor.LogEntries").GetMethod("Clear").Invoke(null, null);`

`Ryan6Vrc.AgentTools.Editor.GrabPhysBone.Run(pbPath, boneIndex, grabberId)` simulates player manipulation of physbones — the door `emulator.md` §Induce routes to. Six doors the caller composes rather than one choreography argument: `Run` grabs by chain address, `GrabPhysBone.Reach(x, y, z, radius, grabberId)` at a reach point (its own door because the spatial query adds preconditions `Run` ignores), `GrabPhysBone.Move(handle, x, y, z)` retargets, `GrabPhysBone.Release(handle, resume)` lets go, `GrabPhysBone.Advance(frames, dt)` steps an exact frame count, `GrabPhysBone.Held()` reports state. A typical arc is `Run` → `Advance(5)` → `Move` → `Advance(5)` → `Release` → `Advance(30)` → `Release(resume: true)`. Play-mode only; every refusal names its own fix.

**Two things its output cannot tell you.** A held grab **pauses the editor**, which is visible to every other tool in the venue — a `RenderThumbnailPlay` Shoot in flight trips its own stall guard — and a bare `Release(resume: true)` with nothing held is the normal unfreeze after settling. And `Advance`'s `dt` pins `Time.fixedDeltaTime` as a **global** clock rescale advancing the animator, every `FixedUpdate` and the emulator's sync-tick accumulators alike: a choreography stepped at a non-default `dt` supports no claim about a transition duration, a sync interval or a debounce window, only about the solve's convergence per unit simulated time.

`Ryan6Vrc.AgentTools.Editor.CheckPackage.Run(assetFolderPath)` / `Ryan6Vrc.AgentTools.Editor.CheckPackage.VerifySelection()` is the deterministic import health check — **missing** (not merely empty) material slots, meshes and scripts, plus two FBX material-remap classes. Distinguishing missing from intentionally-empty submesh slots is the whole point; raw null counts false-alarm. Call it after every vendor import.

The remap classes are the one place an empty slot *is* evidence, and only because the remap says something was meant to fill it: **stale** (entries resolve but one landed on no renderer — force-reimport the FBX) and **unresolved** (entries resolve to nothing — the material pack was never imported: import it **first**, then force-reimport). **The remedies run in opposite order and the wrong one is a no-op, so read which you got.** **Empty slots alone never gate**: a model whose every resolvable entry *did* land carries no verdict however many sit empty — those are other submeshes a reimport cannot clear. Neither class says which slot the map should have filled, because the importer's source-material list does not index-align with renderer slots; so a remap FAIL surviving a force-reimport is a legitimate end state. It keys on the importer's external-object map rather than `materialLocation` — `unity.md` §Sharp edges owns why that distinction bites.

**It reads reference integrity, not what a material draws.** A bare-FBX import whose material pack never arrived, carrying no remap to contradict, is textureless and still PASSes — the render sheet or the material folder settles that case. An empty slot outside a remap likewise routes to the eye, since nearly every one that exists is authored empty (a particle renderer's unused trail slot, a mesh-merging optimizer's destination renderer the build fills). What separates those from a forgotten submesh is whether the slot *should* draw, which the serialized state records nowhere a static read can reach.

`Ryan6Vrc.AgentTools.Editor.ImportPackage.Run(path)` / `Ryan6Vrc.AgentTools.Editor.ImportPackage.Verify(path, expectedRoot)` is the heavy-import door, **two-phase** because `AssetDatabase.ImportPackage` is async and a 60–700MB import outlives the transport window. `Run` validates, pre-writes a RunLog at a stable package-derived path, starts the import and returns immediately — so a transport timeout loses nothing: re-read with `Verify` rather than re-issuing the import. `Verify`'s on-disk walk is **authoritative over the callback-written status**, because an import triggering script compilation reloads the domain and drops the in-flight callback. **Pass `expectedRoot` — it is the normal path, not a fallback. Omit it and a `completed` RunLog returns `PASS` having walked nothing**, merely re-stating the callback's own claim. How often the drop happens is not established, so a `pending` log is unexplained until the root is walked, never a transport story you can assume. Deep import health routes to `CheckPackage.Run`.

`Ryan6Vrc.AgentTools.Editor.ConformImportSettings.Run(scope, whatIf=false)` conforms — `.meta`-only — the five importer settings the VRCSDK refuses an upload over: mip-streaming, max-texture-size, mesh-readable, legacy-blendshape-normals, audio-background-load. Scope is either an **asset folder** (recursive, including assets no avatar references) or a **placed avatar root**, where it walks the set the SDK panel's own validations walk — inactive renderers included, `EditorOnly` excluded — with one named gap: clips an animator **Play Audio** behaviour names stay the panel's. So `whatIf` on a root **previews the panel's importer errors** with the offending paths the panel omits. **Read the prediction off the row list, not the verdict token** — a `whatIf` PASS says only that this door can conform the scope. No build pass can **correct** these (the SDK reads the on-disk importer) and none can be relied on to **mask** them, so the folder form belongs at the **import door**, the avatar form at composition or before an upload, and **neither during a build** — applying means importing. An offender under `Packages/` is named but never written, since a VPM resolve rewrites that tree; copy the asset under `Assets/` and repoint the reference. Re-runnable, no `force` — the door **is** the sanction (`LAYOUT.md` §Vendor mutation enumerates it).

`.controller`/`.anim` files have their own read-only reporters — `ReportController`, `ReportClip`, `CheckAnimator` (whose binding-walk `CheckAvatar` reuses) — contracted in `docs/animator.md`. A merged surface holding an `AnimatorOverrideController`, which none of them can walk, rides `CheckAvatar`/`ReportComposition` summaries as **`unlintableSurfaces=`**: never dropped, never counted among surfaces walked, not folded into the verdict. Neither can a single-controller lint's `undeclaredParam` be read as composed-scope — the name may be declared on another merged controller it never sees. **Handle convention across the read/check family:** an **asset door** (those three) takes the asset it reports, typed *or* path/GUID; a **scene door** (`CheckAvatar`/`CheckSeam`/`ReportShapeOverlap`) takes a scene handle. A wrong-family handle is a loud bare-`FAIL`, never a silent misread.

`Ryan6Vrc.AgentTools.Editor.CheckAvatar.Run(avatarRoot)` names, on an instantiated in-scene descriptor root, the path-encoded reference breaks a base rename leaves after a placement — **MA scene refs** (the `referencePath`+`targetObject` signature: reactive family / BlendshapeSync / Mesh Settings) and **clip/controller bindings** (descriptor playable layers plus every MA MergeAnimator / VRCFury FullController). It resolves every ref against the **placed scene**, so a to-be-merged bone is present pre-bake and resolves now while a base-rename break does not — it predicts nothing about what the build will move and never leans on the `Armature.<Name>` convention. An MA scene ref with **no `referencePath` but a live `targetObject`** is an offender too, not an unset field: `nondestructive.md` owns why the inspector shows it resolved and the build does not. It computes **no** heuristic, and a `clip-binding` offender carries a distinct **`clipAssetPath`** — the field the compose agent routes on: owned/writable ⇒ inline `UC2` clip-fix; `Assets/Vendor/`|`Packages/` ⇒ abort the compose and route to `own-mergeable`.

Two further classes. **`anchor-seam`** names the one-directional break `nondestructive.md` §Choosing a framework rule 1 owns — a VRCFury **`FullController`**-merged binding whose path crosses a tracked MA relocator — and names the **anchor** rather than the binding, the offender field the build's own warning lacks. It asserts the authored shape, not a predicted move: whether that relocator acts in a given build is not evaluated. `Ryan6Vrc.AgentTools.Editor.CheckAvatar.ScanAnchorSeams(root)` is that class alone through a second door, descriptor-free so a bare module prefab scans; `vrc-patterns`' gate drives it and rules a hit FAIL on its own authority. **`merge-conflict`** names ≥2 dynamics components (grouped within a category) resolving to the **same post-merge transform** through `CheckSeam`'s reused merge map, ≥1 mergeable-sourced. MA build-prunes exact-duplicate physbones, so a flagged MA pair may already resolve; the residue (VRCFury physbones, all colliders/constraints, non-exact MA pairs) is where it earns its keep. Each offender is marked live/not-live **relative to the avatar root**, so a mixed-live physbone group reads as the per-range variant set it often is (`outfits.md`) rather than N components to reconcile. Inspection-only; the remedy lives in the skill. It counts binding **paths** (deduped per path + type) where `AnimationUtility` counts **curves**, so the two figures either side of a clip edit are not the same number.

`Ryan6Vrc.AgentTools.Editor.CheckSeam.Run(baseRoot, mergeableRoot)` is the mechanical **fit** companion to that reference check — the pre-render fit gate `verify.md` calls for, since a model cannot read a ~5cm misfit off a sheet. It **reflects the seam's own mapping** (MA `GetBonesMapping()` ∪ VRCFury `ArmatureLinkService.GetLinks()`, never reimplements name-matching) and counts the **weighted humanoid bones**. That count branches the verdict, and **≤1 abstains naming which zero-bone case it is**, because the three route differently: a **BoneProxy** (offset-tolerant seam, operator-positioned — hair/earring/hat/tail; verify the bake), a **MergeArmature that resolved its target and matched nothing** (either the phantom-bone naming mismatch of `nondestructive.md` or a mergeable whose bones are all legitimately outfit-specific — read the names before repairing, and in neither case the bare-prop route), or a **bare prop** (no seam at all; route to `own-mergeable`). A MergeArmature whose **merge target does not resolve** abstains earlier still, naming the `mergeTarget` as the repair. ≥2 gates world-space coincidence at an **ε that scales with the Hips→Head span** over a sub-mm floor, every emit printing the formula it used. Non-humanoid bones never gate — they legitimately deviate up to ~75mm under physbone tuning — and weighted non-humanoid **leaf** bones drop to a bare count, so an end-bone divergence is a hand measurement. Coincidence is one signal across both seam types: MA keeps the offset (a delta ships as the misfit), VRCFury snaps at bake (a delta means the edit-time view is not what ships). Inspection-only; the same world-space mm-drift primitive as `MatchHumanoidRig`'s `poseDriftMm`, position-only.

`Ryan6Vrc.AgentTools.Editor.CheckSeam.CheckBare(baseRoot, mergeableRoot, maxOffsetMm)` is the **pre-seam** door onto that same gate, for the case the seam door is right to abstain on: two side-by-side skeletons with no *resolvable* seam mapping — a fresh refit output beside its target body (`mochifitter.md`), an unplaced mergeable. **Pre-seam does not mean seamless:** a raw refit output does carry a `MergeArmature`, it just has no base to resolve against yet, so what the seam door emits there is the `mergeTarget` abstain and **not** the bare-prop case — read which you got before repairing anything. It pairs by **bone name**, the one place the never-reimplements-name-matching rule does not apply, there being no mapping to reflect. Two differences to drive it correctly: **`maxOffsetMm` has no default**, because a warp solver's residue is ~0.001mm while pre-seam staging is legitimately millimetre-scale and the seam door's ε is two orders of magnitude too loose for a refit; and **ambiguity abstains** (a duplicated armature copy, two base bones sharing a name, both roots resolving to one object) rather than scoring an arbitrary match. It logs to its own `checkseam-bare_*` stem — **never read a bare RunLog as a seam-scored one, the tolerance regimes differ by orders of magnitude.**

`Ryan6Vrc.AgentTools.Editor.ReportShapeOverlap.Run(meshObject, shapeNames, outfitRoot)` fills the coupling blind spot `CheckSeam`/`CheckAvatar` leave — neither reads blendshapes. Over **one** mesh it emits per-shape touched-vertex footprints with pairwise **containment** (`|A∩B| / min(|A|,|B|)`), the locator for the double-subtraction `outfits.md` warns of: a base `Shrink_*` left worn while an outfit `ShapeChanger` shrinks the **same vertices**, invisible to the render sheet and the fit gates.

Both later arguments are optional because it assembles its own co-active set: caller-passed ∪ worn-nonzero ∪ every MA `ShapeChanger` row under `outfitRoot` resolving to **this** mesh. **The third source is the point of the tool and is gated on `outfitRoot`** — those reactions sit at weight 0 at edit time, exactly what the caller's own scan cannot see — so omitting the root silently narrows the set to the first two. On a mixed compose there is no single outfit root: pass the **avatar root**, since per-source runs each manufacture mismatch rows the other root's declarations would have resolved.

`Ryan6Vrc.AgentTools.Editor.ReportClearance.Run(avatarRoot, bodyMesh, chainPrefix)` is the rest-pose clearance digest `fix-clipping` classifies from and re-runs as its rest-contact gate after a collider write. `avatarRoot` is a scene handle; `bodyMesh` a path under it or a descendant name resolving to a SkinnedMeshRenderer; `chainPrefix` (optional) the relative path or name of the chain roots to scope to, and a prefix matching no active chain is a bare `FAIL`, never an empty table. Per chain joint it prints the gap to the nearest baked body vertex against the chain's collision radius there (`bodySlack`; negative = inside the body standing still, which no collider fixes) and the surface-to-surface gap to every collider the chain references (`colliderSlack`; negative = touching at rest). Two tokens are what a rule reads: `restContactCm=` and `insideBodyCm=` per chain, with `restContact=` and `insideBodyAtRest=` counts in the summary. **Read `surface=` before the numbers**: `ndmf-proxy` is the composed preview with reactions applied; `scene` is the raw instance with every reaction at 0, so a shrink the build applies is absent from that clearance. Capsule `height` is the core segment and the collider table prints the measured `endToEnd` (height plus two radii) beside it; `notReferencing` lists the scoped chains a collider does not cover. Chain roots under a VRC constraint are pumped once so a cold editor does not read a stale pose as rest; `constraintPump=unavailable` or `failed` in the summary means those rows may be stale (`emulator.md` §Edit-mode VRC constraints). Edit mode only: no physbone solve, no motion, sampling error about half an edge length — the play-mode number is the skill's harness, not this door.

Three readings of an empty answer, each distinct. **`reacted=0` names its own cause** and never means "nothing anti-clips this". **A `meshCutters` absent token is scoped to `outfitRoot`, not to the mesh** — a cutter placed outside that root and cutting into it is a layout MA supports. **No token at all is an unanswered question, not a "no"**: either no `outfitRoot` was passed or MA drifted, and the reaction sweep withholds identically on MA drift, because otherwise a drifted run's `reacted=0` reads exactly like a clean one. Drift is loud in one direction only — MA absent is a silent no-op, MA installed with the type or member unresolved warns and yields zero reactions.

**A declaration behind a parked ancestor is annotated, not flagged.** MA conditions every reaction on its ancestors' active state, so a row whose every declaration sits under an inactive object may not apply at the initial state. Read the named ancestor and rule: it is dead authoring residue, or something that should be live. **A mismatch still means nothing declared the shape at all**, because proving a declaration dead needs MA's build-time animation index — any clip binding that ancestor's `m_IsActive` keeps the reaction live — which no edit-time read has; flagging without it would invent offenders on every FX-toggled wardrobe. A **report, not a verdict**: a deliberately un-asset-tuned containment floor flags pairs as places to look, and **`map-outfit-shapes` owns the disposition doctrine**. Read-only is not write-free — every run writes its artifact under `SnapshotDir`.

`Ryan6Vrc.AgentTools.Editor.RenderAvatar.Run(target, angles, hide, margin, showGizmos, resolution)` renders **one** avatar subtree in isolation, through the operator's **Scene View**, to a temp contact-sheet PNG with the **NDMF/MA preview resolved**. Read-only: restores the view, leaves the scene un-dirtied. Two framing traps — angles are the six **world** axes, so a rotated target shows the scene's front rather than the avatar's; and it renders the avatar **as the operator has it**, so an eye-hidden child is silently absent from the sheet. Each `hide` entry resolves as a **descendant of the target** and one resolving to nothing **fails the grab** rather than quietly rendering the subtree it named. `CaptureDiff` refuses differently there: it replays frame A's list, where an entry usually stops resolving because the edit under test deleted that object, so its cure is re-grabbing frame A.

**Its ceiling is the point.** A model-read of the sheet is **not** an agent gate — not for fit (quantified `CheckSeam` decides that) and not for clipping. It is operator-eye evidence, the visual companion to `verify.md`; what it shows is the editor *preview*, not the baked upload clone, and headlight shading is truthful for geometry and silhouette, not matcap/rim/fresnel.

**Freshness.** **Grab in a separate call from any edit** — a same-call grab shows the pre-edit proxy — and **one grab per call whenever an NDMF rebuild may be pending**, since grabs batched into one call all refuse while the rebuild is in flight. `gate=armed` means *probed and settled*, **never a guarantee the pixels are current**. `canary=live` is the one that certifies them: the door nudges a drawn blendshape and requires the pixels to move, catching the editor-wide skin-deform freeze (`unity.md` §Sharp edges) that no mechanism-shaped check caught. It certifies **deform, not shading** — a still-compiling shader variant draws a flat placeholder whose pixels move under the nudge just as well. Shading is certified separately and without a token: the door compiles synchronously for its own grabs, counts the placeholder in every frame it serves, and **fails rather than shipping a sheet carrying one**. Absent both tokens, treat **byte-identical pixels around a verified edit as stale**. Mechanism, the three freeze states, and residuals: `agent-tools`' `Tests/Editor/RenderAvatarFreshnessGate.md`. **Grab driven state while still in play** — exiting reverts to authoring state, so a post-exit grab verifies only the static baseline.

**`Ryan6Vrc.AgentTools.Editor.RenderAvatar.CaptureDiff(target, against)` — the door that settles decisions.** `against` is a prior grab's PNG; it pins that grab's framing from the `<png>.cam.json` sidecar, then compares B to A **exactly**, per angle — no tunable tolerance, so no threshold to creep against one avatar. **Each angle's bbox y grows upward from the bottom edge** — read it top-down and a change at the top of the frame localizes to the wrong place, which reads as "no change there". Two phantom-diff traps, told apart by whether a re-grab clears them: `_Time`-driven shading (emission scroll, rim, dissolve) advances between grabs, so only time-static shading is trustworthy; a **DXT1 mask** survives every re-grab — vendor emission/dissolve/glitter masks ship DXT1 in sRGB, where "black" quantizes to 1/255, and the tolerance-free compare then flags the **whole** surface on a masked effect. `map-outfit-shapes` argues keep/hide calls from these, so unlike `Run` its caveats are load-bearing.

**The PNG it returns is frame B, not a diff image** — nothing is painted, so the counts are the whole finding; and A is pinned but never re-probed, so A's freshness and shader notes rode A's own grab summary alone. **Measure the null floor** around any diff an argument rests on — grab twice with no edit between and diff that pair: `changed` is never 0 on a real avatar, drift reaches the same order of magnitude as a real change, and only the measured floor separates them.

## Avatar tools

`com.ryan6vrc.avatar-tools` (from `vrc-unity-tools`, local `file:` ref) is the agent-callable kit for turning a vendor avatar into our own normalized avatar. The package split is by domain, not read-vs-write: `avatar-tools` depends on `agent-tools`, never the reverse, and also carries **standalone clip and material utilities** outside the vendor→owned pipeline (`RepathClips`, `OwnControllerClips`, `RemapMaterials`) — so read its declared domain as *avatar assets*, not *avatar owning*. Every tool is a static method via `execute_code`, writes a JSON RunLog under `RunLogDir`, and is **idempotent**. They share `RemapReferencesByPath`, a path-based remapper rebinding scene references from the vendor hierarchy to ours, duplicate-sibling safe. `nondestructive.md` owns the reference-hardening model that governs what these path-based tools can rebind and what they must preserve.

- `Ryan6Vrc.AvatarTools.Editor.ReportPackage.Run(vendorFolder)` — read-only inventory of a vendor folder. Four fields state their own reach rather than claiming coverage, and each reach is the trap. **`bodyGuess` stays a guess even where the face mesh is a fact**: nothing declares "the body mesh", so it takes the most-blendshapes renderer that is not the face — which on a base whose one body mesh also carries the visemes is something else. The **constraint count is a name-substring rule** (`"Constraint"` anywhere in the type name), which is how it counts Unity's built-ins and VRChat's alike without referencing either assembly, and equally how it counts a vendor's `ConstraintHelper` — an upper bound; reach for `ReportGimmick` when topology matters. **`nonSdkNs`** recognizes no framework by name, so an entry means *a framework is here, go read it*, and components whose script did not resolve are **counted, not skipped**: nonzero means the list is incomplete, not that nothing is there. **`toggles`** resolves FX in two steps, and the second is narrow: a descriptor FX slot names the prefab it resolved from — read that name rather than assuming the first prefab, which may carry no descriptor or an `isDefault` FX layer — failing which, a controller whose **asset path** contains `_FX`, so a folder named `*_FX` qualifies every controller beneath it. **A package whose FX arrives entirely through MA `MergeAnimator` or VRCFury `FullController` from a path without `_FX` therefore reports FX-not-found, which reads like "no FX here" and is not**; `CheckAnimator` resolves those mount points. A framework compiling toggles at build makes `toggles` carry no removability information at all.
- `Ryan6Vrc.AvatarTools.Editor.MatchHumanoidRig.Run(ourFbxPath, vendorAvatarSource)` — builds a fresh humanoid from our own model's skeleton (the bind, so it survives reproportioning) and conforms the vendor's bone mapping + muscle settings onto it, copying a rig wholesale being unreliable. Both arguments are **assets, not scene objects**: an FBX asset path plus the vendor FBX's imported **model root**, whose importer it resolves via `AssetDatabase.GetAssetPath` — a scene instance is a named FAIL. `poseDriftMm` is informational only, expected nonzero after reproportion, and never gates. `Ryan6Vrc.AvatarTools.Editor.MatchHumanoidRig.Preflight(ourFbxPath, vendorAvatarSource)` reports the pre-reimport preconditions without reimporting — the reimport *is* the operation, so there is no `whatIf`.
- `Ryan6Vrc.AvatarTools.Editor.CheckHumanoidRig.Run(ourFbxPath)` — read-only guard asserting each humanoid bone's stored bind (frozen in the `.meta`) still matches the current model's local position, catching a re-export that skipped re-running `MatchHumanoidRig`. **Position-only**: Unity stores a thumb-corrected bind rotation that legitimately differs even on a healthy rig. Its second door `Ryan6Vrc.AvatarTools.Editor.CheckHumanoidRig.InspectAvatar(avatarRoot)` is scene-scoped and answers a different question — on a placed avatar it names the **humanoid-vs-skinned divergence**: a bone mapped to a transform nothing skins (`proxy`, the nearest same-named skinned transform offered as a *candidate*, never asserted), and a transform elsewhere carrying the plain humanoid label while the mapping points somewhere else (`name-shadow`, the class that makes a by-name bone lookup silently wrong). It exists because a rig's mapping lives **only** in the source model's `ModelImporter.humanDescription`, where every prefab, scene, controller and clip reads consistent with the wrong answer. **"Skinned" is decided by bone instance *or* bone name, and the name arm is a declared heuristic**: pre-bake a mergeable's renderers skin its own armature copy, which the build zips onto the base's same-named bone, so an instance-only test reads an ordinary composed avatar as almost entirely proxied.
- `Ryan6Vrc.AvatarTools.Editor.ConformRenderers.Run(ownedRoot, source, ownedToSource=null, whatIf=false)` — both roots are **scene** `GameObject`s (the vendor side is the standalone vendor prefab instance, not an FBX asset root). Assigns vendor materials by renderer name from any source hierarchy, by reference and with no `.mat` copies, and applies the renderer-normalization standard below. A **mergeable** (no humanoid rig / no `Hips`) **PASSes with a note** on the missing anchor rather than FAILing — that missing `Hips` is exactly the input `own-mergeable` prescribes it for; an avatar base still resolves its anchor via `Hips`. It **FAILs on a slot still bound to Unity's built-in `Default-Material`** — run it after materials are remapped.
- `Ryan6Vrc.AvatarTools.Editor.CopyDescriptor.Run(ownedRoot, vendorSource, whatIf=false)` — scene `GameObject`s, same kinds as `ConformRenderers`. Gates on scale + face-blendshape parity, transplants the VRCAvatarDescriptor with refs remapped, and installs a **fresh PipelineManager** (never the vendor blueprint ID). Post-copy it recomputes `ViewPosition` via `FixViewpoint`, non-fatal — a viewpoint miss never flips the transplant verdict.
- `Ryan6Vrc.AvatarTools.Editor.FixViewpoint.Run(ownedRoot, referenceRoot, whatIf=false, ownedLeftEye=null, ownedRightEye=null, referenceLeftEye=null, referenceRightEye=null)` — scene `GameObject`s; recomputes the owned descriptor's `ViewPosition` from a **required** known-good `referenceRoot` (vendor source, or the pre-reshape prior version) plus both rigs' Head + eyes, re-seating the creator's eye→viewpoint offset on the moved eyes rather than snapping to them. **Named FAIL, never a guess**, on a non-humanoid rig, unmapped eyes, or coincident eyes. **Unmapped eyes with the eye objects still present is live vendor config**, so pass explicit `Transform`s per side — both of a side together, the interocular axis needing the pair. Head stays humanoid-resolved, so a non-humanoid rig still FAILs. The `reproportion` skill drives the in-place case; `CopyDescriptor` calls it post-copy.

The **component-transplant kit** — `CopyComponents`, `MoveComponents`, `GraftHierarchy` over a shared transplant core — is **component-agnostic**: selection is a list of **type-name strings** (resolved via `TypeCache`, matched by assignability, fail-loud on ambiguity), so the same tools serve VRC dynamics on a base body and MA/VRCFury/NDMF on an outfit without the package referencing those assemblies. Two tiers: a **deep** tier for the closed, owned VRC set (physbone / collider / contact / VRC-constraint — dependency-follow, `Col_*` leaf-anchor recreate, hard/soft criticality, `force`/scaffold, from a typed table) and a **conservative** tier for everything else (MA / VRCFury / NDMF / unknown / Unity built-in constraints — `CopySerialized` + generic object-ref remap, leave-missing-missing). The **reach root** `(vendorSource, ownedRoot)` bounds the remap: refs to objects under the vendor source rebind to our counterparts; out-of-reach refs are left for placement-repair.

A **differently-named armature-root GO** (owned `Armature.1` vs vendor `Armature`) nulls every ref through it under that name-based matching. `CopyComponents` / `GraftHierarchy` take an optional `vendorToOwned` map (injective, **case-sensitive**) that reconciles it — one entry covers hosts and relocated-outside-armature anchor refs alike. An absent map is a no-op; a non-injective or ambiguous map is a **named FAIL in both `whatIf` and execute**, never a silent mis-bind.

**The remap moves the OBJECT half of an MA scene ref, never the `referencePath` string** — out of scope in every transplant tool, deliberately, because repathing would mean guessing an avatar frame the tool does not have (the prescribed copy source is a standalone vendor prefab with no descriptor). It usually costs nothing, since hosts land at the same indexed path and a ref carrying both halves resolves off the live `targetObject` first — **but only while that target lands under the avatar root** (`nondestructive.md` §Reference hardening). So it bites where the destination path genuinely differs — a `vendorToOwned` segment rename, or a reach root that is not the avatar root on either side — and then only for a path-only ref, which is the shape that doc tells you to author. **Run `CheckAvatar` after either shape.**

**Rename-map direction — the kit runs two, pointing opposite ways.** A rename map's **key** names the hierarchy its tool **walks**; its **value** the hierarchy that tool **resolves into**. So the transplant tools (walking vendor, resolving into ours) take `vendorToOwned`, while `ConformRenderers` (walking our renderers, resolving into the source) takes `ownedToSource` — and holding "one map" across both gets one backwards. Two consequences: `vendorToOwned` **must be injective** to address a unique dest sibling (enforced), where `ownedToSource` is legitimately **many-to-one** (two owned meshes taking one source renderer's materials); and `vendorToOwned` matches **Ordinal** where `ownedToSource` matches **case-insensitively**. Trust the parameter names over the shape of your map.

- `Ryan6Vrc.AvatarTools.Editor.CopyComponents.Run(ownedRoot, vendorSource, typeNames, force=null, vendorToOwned=null, whatIf=false)` — reproduce all components of the named types onto our rig, **additive + idempotent** (count-parity skip per `(host, type)`; never destroys). Copy from the **standalone** vendor source, not an outfit already placed in an avatar. **A flagged-missing host is PASS** — a prune-backstop list to triage by forcing the key (`vendorRelativePath :: ComponentType`), re-pruning, or accepting — and is classified **`[bone]`** (a skeleton bone absent on our rig, a genuine prune/rename divergence) or **`[holder]`** (a non-bone GO the source parked the component on, deep-tier only). A collider/contact whose holder sits directly under a **surviving bone** is auto-recreated instead and never appears in the `[holder]` set. Forcing `[holder]` keys scaffolds those holders back, which **reconstructs the grouping, so a following `MoveComponents` is redundant**. Force-all-`[holder]` is safe **only** where the target is a faithful re-export (the reproportion twin/copy case); on the vendor→owned path a `[holder]` may be a deliberately-pruned accessory.
- `Ryan6Vrc.AvatarTools.Editor.MoveComponents.Run(ownedRoot, targetRoot, typeNames, destPath, whatIf=false)` — relocation primitive; `ownedRoot` is a `GameObject` and **`targetRoot` a `Transform`**. Matches components whose effective anchor descends from `targetRoot`, mints a holder under `destPath`, pins each anchor to its original transform, and rewires inbound serialized refs to each re-created component — behavior-neutral, **never moves a bone**. Matching is by **anchor, not current location**: a later call with a broader `targetRoot` re-captures components an earlier narrower call already grouped, leaving stale empty holders — **order the calls broad→narrow**. Anchor field per type comes from the VRC table; a targeted type with **no table anchor FAILs loud** (refusing MA/VRCF/NDMF *and* Unity built-in constraints). Idempotent; run **pre-prefab**.
- `Ryan6Vrc.AvatarTools.Editor.GraftHierarchy.Run(ownedRoot, vendorSource, subtreeRoots, vendorToOwned=null, whatIf=false)` — copies named GO **subtrees wholesale**: scaffold the full structure (vendor verbatim local TRS) + copy **all** components on every GO, type-blind, remapped against the reach root. For pulling an outfit's authoring/menu subtree without listing every GameObject. Inverted contract vs `CopyComponents`: a missing host is **expected**, never flagged. Count-parity + reuse-by-path idempotent.

The **controller owning/consolidation kit and the compile/decompile substrate** — `CleanController`, the clip-repathing pair, `CompileController`/`DecompileController`, and the `SchemaValidation`↔`ControllerRules` split — are `avatar-tools` members obeying the same conventions. Their contracts, the `Decompile→Compile` round-trip that reframes the owning tools, and the YAML authoring language are in `docs/animator.md` (schema: `docs/animator-schema.md`).

Two standalone **scene utilities** round out the kit, each simple enough that its signature is the contract. `Ryan6Vrc.AvatarTools.Editor.RemapMaterials.Run(root, replacements, whatIf=false)` — swap materials by **asset path** across a hierarchy, in place, `replacements` an old-path ⇒ new-path map: no source hierarchy and no name matching, a different operation from `ConformRenderers`' copy-by-renderer-name. `Ryan6Vrc.AvatarTools.Editor.ConstrainedDuplicate.Run(sourceRoot, kind, direction, includeRootBone, solveInLocalSpace, stripClonedConstraints, replaceExisting, duplicateSuffix, whatIf)` — clone a hierarchy and wire VRC constraints between original and duplicate bones; every parameter after `sourceRoot` is defaulted, and the two enums are declared beside the tool. **It bakes each original's current pose into the constraint as a zero-offset locked source, so pose first and duplicate second** — a pose applied afterwards is driven back every frame.

The **`own-base` skill** (in `vrc-skills`) orchestrates these — it holds the judgment, gates, and sequencing; the tools hold the mechanics.

**Renderer-normalization standard:** every renderer's bounds are **ensured ≥** an origin-centred anti-cull floor (the box `ConformRenderers` declares) — grown to it, never shrunk, so a deliberately larger box survives — the Anchor Override is set to **Hips** only when invalid (null or not a child of `ownedRoot`), a valid internal anchor preserved, and a null Root Bone filled with Hips. Not copied from the vendor, creators getting these wrong. On a *composed* avatar, Modular Avatar `Mesh Settings` can own bounds/anchor at build — there the tool's writes are authoring-only, **so its PASS is not a runtime guarantee.**

`Ryan6Vrc.AvatarTools.Editor.OwnMaterial.Run(materialPath, outDir=null, forkTextureSlots=null, newName=null, force=false, whatIf=false)` brings a vendor material into ownership and forks the **named** texture slots into the owned copy's own namespace — **every unforked slot keeps its source-GUID reference**, and the provenance table it returns is the caller's gate. Routing is target-identity: `outDir` given ⇒ own a vendor source (or branch an owned one) into a NEW `.mat`; `outDir` omitted ⇒ augment the already-owned source in place. A locked-Poiyomi copy is unlocked via Thry's ShaderOptimizer — it **refuses** rather than risk Thry's blocking dialog when the original-shader tag cannot resolve, and leaves the vendor source untouched. The `own-material` skill holds the judgment of which slots to fork.

## Thumbnails

`Ryan6Vrc.AvatarTools.Editor.RenderThumbnail.Run(target, pose=null, expression=null, framing="bust", bg=null, fov=30f, yaw=null, whatIf=false)` (edit mode, the default) and `RenderThumbnailPlay` (play mode, a session) are two front-ends over one camera/capture spine — same caller vocabulary, a 1200×900 PNG that feeds `UploadAvatar`. Edit mode is one synchronous baked call. Reach for play mode only when dynamics or FX must be truthful: it renders with hair/cloth **settled** by the real physbone solver and FX toggles/materials **resolved**. Neither refusal nor exception paths write a RunLog, **so a RunLog's absence does not mean a door went undriven.**

Play is a **session**, not a call (physbones need the player loop, and the tool cannot flip play itself): `Ryan6Vrc.AvatarTools.Editor.RenderThumbnailPlay.Run(target, scenePath=null)` → `manage_editor play` → `Ryan6Vrc.AvatarTools.Editor.RenderThumbnailPlay.Shoot(pose, expression, framing, bg, fov, yaw, settleFrames)` (async — poll `Ryan6Vrc.AvatarTools.Editor.RenderThumbnailPlay.Status()`) → `manage_editor stop` → `Ryan6Vrc.AvatarTools.Editor.RenderThumbnailPlay.End()`. One `Run` serves many `Shoot`s. Toggle/menu-param state set in play survives a `Shoot`, **but layer state a param does not imply, e.g. trigger-latched, does not.** **Settle is never asserted** — the verdict names any chain still moving at capture, so an `OK` alongside a populated moving-chain list is rendered-but-not-settled and the shot is not the settled one you asked for. The venue is a loaded scene lit by its own lights, not edit mode's fixed rig; `End` reopens it from disk, **discarding the pose and emulator edits**. Because that reopen discards anything a loaded scene holds that its file does not, `Run` compares each loaded `Assets/` scene against its file and refuses on a real difference — not on `isDirty`, which is wrong in both directions (`unity.md` §Sharp edges) — framework churn discounted, so a refusal here is work, not noise. `Run` also copies those scenes to `Temp/` first, which is the recovery path when a difference the comparison did not recognize gets restored away.

## Publish

`Ryan6Vrc.AvatarTools.Editor.UploadAvatar.Run(avatars, whatIf=false)` (a `GameObject[]`) batch-uploads composed avatars live to VRChat, driving Continuous Avatar Uploader (CAU) by reflection. **Operator-gated** — the `upload-avatar` skill's explicit "upload now" is the only trigger, never autonomous — and fail-loud, separating an environment that is not ready from a genuine upload rejection. The not-logged-in case self-heals: the door kicks CAU's saved-credential restore itself, so it normally costs one re-run; the operator's interactive sign-in is the only login it cannot reach. It runs async, so poll `Ryan6Vrc.AvatarTools.Editor.UploadAvatar.Status()` until it stops reporting running. A per-handle attempt ceiling counts *consecutive* failures so account safety does not lean on skill prose, and **no blueprint id ever enters output** (public-repo safety). **`whatIf` reads the environment and the handles, never the avatar**: it does not evaluate whether an avatar builds — `ReportComposition.Run(avatarRoot, bake:true)` answers that. Nor is it side-effect-free: the preconditions run first, so the first `whatIf` after a domain reload may issue the saved-credential network request and change in-memory SDK auth state. **CAU saves the scene it uploaded from**, to persist the minted blueprint id — committing whatever else that scene held, with nothing left to diff against afterwards. The only defence is a `saveAsCopy` taken before the call and byte-compared after.

**An upload cannot rename.** CAU sends a name exactly once, on the new-avatar path; an update's record carries the *live* name, re-fetched immediately before the bundle write, so anything staged is discarded. Two consequences that bite silently: a GameObject rename never reaches an uploaded avatar's display name, and a re-upload republishes under the **old** name with no warning. The scene is therefore not evidence about what is published — `Ryan6Vrc.AvatarTools.Editor.ReportAvatarRecord.Run(avatar)` is, reading the live blueprint record as the server holds it. Both record doors are **async on `UploadAvatar`'s pattern**, the summary naming the poll to make (`Ryan6Vrc.AvatarTools.Editor.ReportAvatarRecord.Status()`, `Ryan6Vrc.AvatarTools.Editor.UpdateAvatarRecord.Status()`).

`Ryan6Vrc.AvatarTools.Editor.UpdateAvatarRecord.Run(avatar, expectCurrentName, newName=null, newDescription=null, newTags=null, newImagePath=null, whatIf=false)` changes a live record — name, description, tags, thumbnail. No bundle, no re-upload. Every field is **null-means-unchanged**, which makes an empty tag array the only way to say "clear the tags" — and a call that sets nothing refuses rather than posting the record back unchanged, since that would bump the server's version and report success for an edit that never happened.

**An image is a second write that can fail alone, and no read can confirm it landed:** the call writes `ImageUrl` while `hasThumbnail` reads `ThumbnailImageUrl`, already true on anything ever uploaded. So the door's own report is the only evidence there is — `ReportAvatarRecord` afterwards proves nothing either way.

The metadata call hands the API a whole record, and why that is safe needs stating precisely, because the obvious reading is wrong. The bundle and thumbnail survive **that** call because the SDK **never submits them** — it narrows the record to a changes payload internally — not because the server tolerates a full post. Description, tags, release status and styles *are* submitted, round-tripped from the read. **So the guarantee is "the fields you didn't set are written back as they were", not "untouched"**: a concurrent writer between the read and the write gets reverted, and the sibling calls taking the same record genuinely do write the heavy parts.

It requires `expectCurrentName` and refuses on mismatch, chained from `ReportAvatarRecord`'s reported name, because the write targets whatever `blueprintId` the `PipelineManager` holds — an id the caller never sees — and a stale one would land the edit on a different published avatar. Treat it as a **best-effort confirmation, not a compare-and-swap**: the read and the write are separate requests with no server-side conditional, so a name that changes in between is not caught, and a display name is not an identity, so a stale id pointing at an identically-named record still passes.

Retyping that name rather than chaining it will usually refuse, because **VRChat sanitizes submitted text server-side**: an ASCII period comes back as U+2024 ONE DOT LEADER, and the two are visually identical. This is not name-specific — descriptions and the API's own error strings arrive sanitized the same way — so match any published value against the *landed* form only.

Two things are deliberately absent and should stay that way. `ReleaseStatus` is not settable: it is the field that makes an avatar public, and folding an irreversible visibility change into a general metadata setter is how it gets flipped by a caller who was only fixing a typo. `DeleteAvatar` sits one method away in the same API and is not built at all.

Two traps for anything else built on `VRC.SDKBase.Editor.Api.VRCApi`, both cheap to get wrong: it carries its **own** auth, so `APIUser.IsLoggedIn` can read `False` while reads and writes succeed — gate a `VRCApi` door on it, as `UploadAvatar` legitimately does for CAU, and you refuse a working environment. And `ApiErrorException.Message` is the content-free default string; the status and the server's real text live in its `StatusCode` and `ErrorMessage` **fields**. A 404 there means "no such record **or** not visible to this account" — the API does not distinguish them, so neither should a diagnostic.
