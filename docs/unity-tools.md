# Unity agent tools

Per-tool contracts for the agent inspection harness (`agent-tools`) and the vendor→owned avatar kit (`avatar-tools`) — the static-method tools called via `execute_code`. The cross-cutting conventions (which families take string handles and which take typed refs, the namespace-vs-assembly split, the `whatIf`/`preflight` preview grammar) and the MCP/sharp-edges operating knowledge live in `unity.md`; read it alongside this. Controller and clip tooling contracts are in `animator.md`.

## Inspection & reporting (agent-tools)

Shipped as the `com.ryan6vrc.agent-tools` package (from `vrc-unity-tools`, consumed via a local `file:` ref); also home of the shared reporting conventions (`RunLogFormat`, the `[AgentTool]` marker). `RunLogFormat.WriteRunLog(dir, label, summary, body, ext)` is the body-agnostic writer every non-transplant emitter routes through: it owns the dir + timestamped filename and appends the in-band
`| log=<path>` trailer, or returns a bare-FAIL with no trailer when the write fails. `RunLogDir`
(`Assets/Agent/RunLogs/`, verdict records) and `SnapshotDir` (`Assets/Agent/Snapshots/`, read-only captures) are the single declarations of the two output dirs.

**Invocation & preview grammar** — the handle-style split, the `Ryan6Vrc`/`Ryan6VRC` namespace-vs-assembly split, and the `whatIf`/`preflight` preview grammar every tool here (and in §Avatar tools) obeys live in `unity.md` §Agent-callable tools. Every door in this section is string-handled; §Avatar tools is the half that splits. `execute_code` compiles your snippet as a **method body**, so a `using` directive can't sit at the top (the proxy refuses it) — **fully-qualify each call**: `Ryan6Vrc.AgentTools.Editor.<Tool>.<Method>(…)` for the tools here, `Ryan6Vrc.AvatarTools.Editor.<Tool>.<Method>(…)` for §Avatar tools. The type namespace is `Ryan6Vrc` and the `.Editor` suffix is required — both are the recurring stumble.

`AgentInspector` walks selected/scene objects (incl. VRChat components, generically via `SerializedObject`) to JSON under `AvatarProject/Assets/Agent/Snapshots/`; the
written path is emitted in-band on the console line (`… => OK | log=<path>`), with the artifact's `bytes=` beside it — a whole-hierarchy walk of a complex vendor avatar runs past the agent read cap, and past it the summary also names the narrower doors that would fit. The artifact is never truncated to get there; only the summary is windowed. Agent door:
`AgentInspector.Snapshot("Root/Child/Path", includeChildren, followAssets)` snapshots by hierarchy path and returns that summary. Any objectReference resolving to a saved asset carries `guid`/`fileId` (sub-asset-safe) **unconditionally**, so every ref is edit-addressable; a scene-object ref keeps its `scenePath` instead. `followAssets` additionally inlines a generic `SerializedObject` dump (`fields`, recursive) of each **ScriptableObject-asset** ref — a `VRCExpressionsMenu` `subMenu` chain or `VRCExpressionParameters` expands to the whole tree in one snapshot. Non-SO assets (meshes, clips, controllers) get identity only, not expansion (no overlap with `ReportController`/`ReportClip`). The expansion is bounded by asset-hop depth and a walk-wide budget, and every cut is signaled inline (`assetDepthCapped`/`budgetSkipped`/`alreadyDumped`) plus a top-level `assetsTruncated` count — it dumps raw values; decoding them stays yours.

`ReportGimmick` sits opposite `AgentInspector` on that axis: where `AgentInspector` dumps one object's raw fields and leaves decoding to you, `ReportGimmick` interprets a whole gimmick subtree into a compact digest — constraint edge-lists, physbone/contact tables, and mechanically-certain idioms — and is complete by construction: a generic tier-2 census names every component no table interpreted (Modular Avatar, custom scripts, broken scripts) with a one-struct-level scalar peek, so `other=0` genuinely means empty. This is also why you let the tool read the avatar rather than hand-grepping prefab YAML: Modular Avatar components serialize by script **GUID** (MergeArmature is `2df373bf…`), never the string `MergeArmature`/`nadena`, so a name grep of the YAML finds nothing. Reach for it to reason about a gimmick's topology; drop to `AgentInspector.Snapshot(<host path>)` only for what's past that shallow peek — a component's nested structs, arrays, or followed assets. Its physbone table's **`chain subtree`** cell (`bones=/skinned=/hosting=`) censuses the bones each row's physbone reports as its own chain — how many some renderer skins at nonzero weight, how many carry another component. **Reported, not judged, and deliberately not a dead-chain verdict**: a pre-bake bone that will name-merge onto a base bone reads `skinned=0` because the base mesh skins the *base* transform, and a chain whose consumer sits outside it reads all-zero while load-bearing. The set is the component's own chain membership, with its declared exclusions already applied — which is still not a claim about which bones *move*.

`ReportComposition.Report(avatarRoot, bake=false, paramFilter=null)` answers the one question no other door here crosses the seams for: **where behaviour comes from on a composed avatar**. Per parameter it reports the declaration, every writer and every reader, per merged surface — the descriptor's playable layers, each MA MergeAnimator, each VRCFury FullController — plus the merge-surface table itself and the authored menu-control union across the descriptor menu, every FullController's `menus[]`, and the MA installers and menu items. It earns its place because deciding whether one toggle exists routinely takes five artifacts, each of which reads perfectly consistent on its own with the wrong answer: `ReportGimmick` reports a declared `parameter` field and by contract never traces it into an animator, `ReportController` sees one controller, and `CheckAvatar` is a gate on reference integrity. Scene door (hierarchy path), read-only, artifact to `SnapshotDir` with a windowed summary; `paramFilter` narrows every parameter table to matching names so chasing one parameter costs one row rather than the whole avatar.

**One door, two modes — and the verb is settled, not open.** Plain (the default) is the **authored** census and says so in its own cells; `bake:true` measures the composed truth by building a throwaway clone through the VRC SDK preprocess chain and diffing it against that census, emitting a per-parameter verdict for every authored name. The flag only upgrades exactness on one subject, so this is a `Report` with a completeness flag and **not** a `Compare` — a `Compare` takes two caller-supplied subjects, and here the caller supplies one and the tool derives the second view. **The category set is the bake artifact's own to name**: read the legend it prints, which is canon and deliberately not echoed here. What holds across it — every authored **name** gets exactly one verdict and those verdicts sum to the reported parameter count (one row can stand for several names, so count names, not rows); each row names the **owning surface** that performed what it reports; built names no authored one claims are reported apart from them and are not findings; and attribution is **inference** — a pass-through name matches directly, a prefixed one is recovered by suffix plus owning surface, an unresolvable one says so rather than guessing, and no build-time naming grammar is pinned anywhere. The `synced` / `saved` / `default` columns are **authored in both modes**, so no artifact from this door is evidence about sync state (`runtime.md` §VRCFury build-time reshaping owns why, and where the build records what it did).

**Bake mode is two-phase, and its failure is loud.** The preprocess chain outruns the MCP transport window, so `Report(…, bake:true)` writes its artifact path to disk *before* starting the work and returns `… => PENDING | log=<path>`; `ReportComposition.Verify(avatarRoot)` re-reads the verdict from it. A transport timeout therefore loses nothing and the call must not be re-run — a duplicate while one is in flight returns the same path rather than starting a second build. Freshness is by construction: the tool builds its own clone, destroys it after the read, and never consults a leftover under `Packages/com.vrcfury.temp/` (those reflect the VRCFury version that made them). **A bake failure names the failed stage and publishes no parameter table at all** — never a silent fallback to authored-only output, because authored rows under a heading promising composed truth is the misread the whole door exists to prevent. Cost is measured in the parameter description; default off, since cheap and safe is the default and exactness is opt-in.

**Two scope rules make its empty cells readable.** An empty writers cell renders `writers=(none among scanned surfaces; menu/contact/physbone/OSC not excluded)` **in the cell**: the writer set for a parameter is open, so "nothing writes this" is not a claim any static read can make, and a blank cell would re-manufacture exactly the false claim this tool was built to stop. Plain mode likewise makes **no** namespace-resolution claim — its cells read `authored names; the build may rewrite them — bake:true resolves`. Completeness follows `ReportGimmick`: a tier-2 census names every component no table interpreted, so `other=0` genuinely means empty. `optimizers=` is a **census line only** — no detect/disable/re-enable machinery, because the full chain is what ships; an agent wanting a pre-optimizer view disables those components itself first.

**Boundaries it declares rather than leaves to discovery.** Against `AgentInspector.Snapshot(followAssets:true)`, which expands a `VRCExpressionsMenu` subMenu chain as a generic raw-field dump: this door reports the typed authored control *set* across every installer and dumps no raw fields, so drop to `AgentInspector` for a control's nested structs. Against `CheckHumanoidRig.InspectAvatar`: humanoid mapping is not read here and is routed **by name in output text**, never called — `CheckHumanoidRig` lives in `avatar-tools`, which depends on `agent-tools` and not the reverse.

`ReportConsole.Report(types, filterText, count, includeStackTrace, stripBenign, collapseDuplicates)` reads the Editor console — every line of every entry. `types` (`error`/`warning`/`log`/`all`) is decided by the entry's `mode` bits, and `filterText` matches the whole entry — body and callstack — rather than just the header. The body/callstack split is the index Unity itself records (`LogEntry.callstackTextStartUTF16`), not a guess at which lines look like frames, so no payload line can be lost to the split; `includeStackTrace` defaults on, and turning it off still counts the withheld frames rather than dropping them silently. Output is inline, unlike the artifact-writing report tools — the message text is itself what you came for — spilling to a Snapshot past a budget. It writes nothing to the console it reads, so it never pollutes its own next read. **It reads the Console *window's* rows, so that window's own filters bound it** — a search term in the Console's box, a cleared severity toggle, or Collapse all narrow what any console read can see, and a search filter can take the visible count to zero on a console full of errors. Unity exposes no unfiltered enumerator, so this is not avoidable; it is detectable, because `LogEntries.GetCountsByType` is *not* filtered. `ReportConsole` compares the two and reports the gap as a count — `UNREACHED=4/8 entries are hidden from this read by the Console window [search="foo"] — THIS IS A FILTERED VIEW` — so a narrowing mechanism nobody enumerated still shows up. It never changes those filters: an `UNREACHED=` note is the operator's Console window to fix, not the tool's. When the hidden entries themselves are needed, `Application.consoleLogPath` (Editor.log) is the unfiltered text of record, process-wide and unstructured. Clearing has no door here, and `UnityEditor.LogEntries` is internal, so the `execute_code` form is reflective: `typeof(UnityEditor.Editor).Assembly.GetType("UnityEditor.LogEntries").GetMethod("Clear").Invoke(null, null);`

**`stripBenign` defaults on, and you usually want it there.** Four families are known noise — MACS load chatter, `DestroyBlendTreeRecursive`, the FBX importer's inconsistent-result line, and VRCFury build progress — and Unity types several of them as genuine **errors**, so reading the entry's type will not separate them from real ones however faithfully you do it. An unfiltered `types:"error"` read during a build buries the diagnosis you ran it to find. The strip stays honest by never being silent: the summary names each family and count it removed (`benign-stripped=[…]`), so a dropped entry is still visible as a number. An entry kept because it matched `filterText` is exempt, so filtering *for* noise by name still returns it. Pass `stripBenign: false` when you want the raw buffer.

**`collapseDuplicates` also defaults on**, on that same never-silent contract: byte-identical entries (body + callstack) fold into one row carrying `×N`, and the summary reports `collapsed=`. It keeps the **last** occurrence, because `count` clamps from the newest end — an oldest representative can be clamped away, erasing the recurrence from the read taken to see it. So `count` bounds *rows*, and the window can reach further back than that many entries. A `filterText` match is exempt, which is what keeps `emulator.md`'s tagged-probe idiom whole: there the identical repeats *are* the series. Distinct from the Console window's own **Collapse**, above.

`CheckPackage.VerifyFolder(path)` / `VerifySelection()` is the deterministic import health check — reports **missing** (not merely empty) material slots, meshes, and scripts, plus two **FBX material-remap** classes. Its
one-line PASS/FAIL summary ends with the RunLog path in-band (`… => RESULT | log=<path>`); a bad-input
early return is a bare `[CheckPackage] FAIL: …` with no trailer. Distinguishing missing from intentionally-empty submesh slots is the whole point; raw null counts false-alarm. Call it after every vendor import.

The remap classes are the one place an empty slot *is* evidence, and only because the remap says something was meant to fill it: **`remapSTALE=`** (entries resolve, the model still imports empty — force-reimport the FBX) and **`remapUNRESOLVED=`** (entries resolve to nothing — the material pack was never imported: import it **first**, then force-reimport). The remedies run in opposite order and the wrong one is a no-op, so read which token you got. Both gate the verdict. The check keys on the importer's external-object map rather than `materialLocation`; `unity.md` §Sharp edges owns why that distinction bites.

**It reads reference integrity, not what a material draws.** A bare-FBX import whose material pack never arrived, carrying no remap to contradict, is textureless and still PASSes. Counting textureless materials does not close that gap and was measured and declined: vendor FBXs routinely bind their own embedded placeholder materials, which the prefabs override, so the count reads nonzero across healthy packages — ambient, not diagnostic. The render sheet or the material folder settles this case; the remap classes catch it wherever a remap exists.

`ImportPackage.Import(path)` / `ImportPackage.Verify(path, expectedRoot?)` is the heavy-import door, and is **two-phase** because `AssetDatabase.ImportPackage` is async and a 60–700MB import outlives the MCP transport window. `Import` validates, pre-writes a RunLog at a **stable, package-derived path**, starts
the import, and returns immediately (`… => PENDING | log=<path>`); `whatIf` validates only and reports
`wouldLog=`. A transport timeout on `Import` therefore loses nothing — the RunLog is already on disk, so re-read it with `Verify` rather than re-running the import. `Verify` re-reads that RunLog and walks the on-disk `expectedRoot`, emitting PASS / PENDING / FAIL; the on-disk walk is **authoritative over the callback-written status**, because an import that triggers script compilation reloads the domain and drops the in-flight callback (leaving the log stuck at `pending`). **Pass `expectedRoot` — it is the normal path, not a fallback.** How often that drop actually happens is unmeasured, so a `pending` log is unexplained until the root is walked, never a transport story you can assume. `Verify` routes deep import health (missing refs / stale remap) to `CheckPackage.VerifyFolder` rather than duplicating it.

`ConformImportSettings.RunFolder(assetFolderPath, whatIf=false)` conforms — `.meta`-only, recursively — the five importer settings the VRCSDK refuses an upload over: `mip-streaming`, `max-texture-size`, `mesh-readable`, `legacy-blendshape-normals`, `audio-background-load`. No build pass can **correct** them (the SDK reads the on-disk importer) and no universally-present pass can be relied on to **mask** them, so it belongs at the **import door and never during a build** — applying means importing. `whatIf` reports without writing (`PASS`); an apply is `PASS`, or **`NOT-PASS`** naming any write that did not reach disk; an invalid or over-broad root is a bare `FAIL`. Re-runnable, no `force` (the door is the sanction; `LAYOUT.md` §Vendor mutation owns the permission), and a texture whose cap lands **below its source** is named as a fact — never as a render debt, since a blocked upload leaves no shipped baseline to compare against.

`.controller`/`.anim` files have their own read-only reporters — `ReportController`, `ReportClip`, `CheckAnimator` (whose binding-walk `CheckAvatar` below reuses) — contracted with the rest of the animator tooling in `docs/animator.md`. **Handle convention across the read/check family:** an **asset door** (these three) takes the asset it reports — the typed `AnimatorController`/`AnimationClip` *or* its **path/GUID** — while a **scene door** (`CheckAvatar`/`CheckSeam`/`ReportShapeOverlap` below) takes a **scene handle** (hierarchy path / instance-id / name). A wrong-family handle is a loud bare-`FAIL`, never a silent misread.

`CheckAvatar.Inspect(avatarRoot)` is the scene-scoped companion to those digests: on an instantiated in-scene avatar (descriptor) root it names the two path-encoded reference breaks a base rename leaves after a placement — **MA scene refs** (the `referencePath`+`targetObject` `AvatarObjectReference` signature: reactive family / BlendshapeSync / Mesh Settings) and **clip/controller bindings** (descriptor playable layers + every MA MergeAnimator / VRCFury FullController). It resolves every ref against the **placed scene** — a to-be-merged bone is present pre-bake and resolves now, a base-rename break does not — so it predicts nothing about what the build will move and never leans on the `Armature.<Name>` convention. An MA scene ref with **no `referencePath` but a live `targetObject`** is an offender too, not an unset field: `nondestructive.md` owns why the inspector shows it resolved and the build does not, and what the build does instead depends on the consumer (the reactive family resolves nothing; a MergeAnimator `relativePathRoot` silently falls back to the component's own GameObject). Its verdict is **`CLASSIFY`** (unresolved refs found — a finding for the agent to route, not a tool failure), distinct from `PASS` and a bad-input bare `FAIL`. It computes **no** heuristic — it names each offender and its class, and a `clip-binding` offender carries a distinct `clipAssetPath` (the field the compose agent
routes on: owned/writable ⇒ inline `UC2` clip-fix; `Assets/Vendor/`|`Packages/` ⇒ abort the compose and
route to `own-mergeable`). A third class, **`anchor-seam`** (also `CLASSIFY`), names the one-directional break `nondestructive.md` §Choosing a framework rule 1 owns — a VRCFury **`FullController`**-merged binding whose path crosses a tracked MA relocator — and names the **anchor** rather than the binding, the offender field the build's own warning lacks. It asserts the authored shape, not a predicted move: whether that relocator acts in a given build (each needs its target to resolve) is not evaluated, and the emitted scope note bounds what a zero count covers. `CheckAvatar.ScanAnchorSeams(root)` is that class alone through a second door, descriptor-free so a bare module prefab scans; `vrc-patterns`' gate drives it and rules a hit FAIL on its own authority (`CONVENTIONS.md` §The gate). It also names a **`merge-conflict`** class (also `CLASSIFY`): ≥2 dynamics components (physbone / collider / VRC-constraint, grouped within a category) that resolve to the **same post-merge transform** through `CheckSeam`'s reused merge map, ≥1 mergeable-sourced (the raw target being a map key excludes a pure base↔base duplicate — no baseline needed). MA build-prunes exact-duplicate physbones, so a flagged MA pair may already resolve; the residue (VRCFury physbones, all colliders/constraints, non-exact MA pairs) is where it earns its keep. Each offender is marked `[live]`/`[not-live]` **relative to the avatar root** (per category — a VRC constraint's `IsActive` counts alongside `enabled`), so a mixed-live physbone group reads as the per-range variant set it often is (`outfits.md`) rather than N components to reconcile. Inspection-only — no scene dirty, no `.anim` write; the remedy lives in the skill, not the tool.

`CheckSeam.Check(baseRoot, mergeableRoot)` is the mechanical **fit** companion to `CheckAvatar`'s reference check — the pre-render fit gate `verify.md` calls for (a model can't read a ~5cm misfit off a sheet). It **reflects the seam's own mapping** (MA `GetBonesMapping()` ∪ VRCFury `ArmatureLinkService.GetLinks()`, never reimplements name-matching) and counts the **weighted humanoid bones** (a mapped bone whose base side is humanoid and whose merge side a mergeable mesh skins). The count branches the verdict: **≤1 → `REFUSE`**, naming which zero-bone case it is — a **BoneProxy** (offset-tolerant seam, operator-positioned — hair/earring/hat/tail; verify the bake), a **MergeArmature that resolved its target and matched nothing** (either the phantom-bone naming mismatch of `nondestructive.md` or a mergeable whose bones are all legitimately outfit-specific — read the names before repairing, and in neither case the bare-prop route), or a **bare prop** (no seam at all; route to `own-mergeable`), which the skill routes differently on; a MergeArmature whose **merge target does not resolve** abstains earlier still, naming the `mergeTarget` as the repair; **≥2 → gate** world-space coincidence at an **ε that scales with the Hips→Head span** over a sub-mm floor — `CheckSeam.cs` declares both constants once and every emit prints the formula it used, so read the ε in force off the verdict line rather than a number here → `PASS`, or `NOT-PASS` with worst-first offenders and `maxOffset=Nmm` (sub-mm noise vs wrong-base reads at a glance). Non-humanoid bones never gate — they legitimately deviate up to ~75mm (physbone tuning). Coincidence is one signal across both seam types: MA keeps the offset (a delta ships as the misfit), VRCFury snaps at bake (a delta means the edit-time view isn't what ships). `REFUSE` (bare line, no trailer, like `CheckAvatar`'s bad-input `FAIL`) also fires on a seam that won't resolve onto this base, seams that disagree, a non-humanoid base, or a VRCFury bake-time scale — abstain-class (proxy, unresolvable) at warning, reflection drift at error. Inspection-only; the same world-space mm-drift primitive as `MatchHumanoidRig`'s `poseDriftMm`, position-only.

`CheckSeam.CheckBare(baseRoot, mergeableRoot, maxOffsetMm)` is the **pre-seam** door onto that same gate, for the case `Check` is right to abstain on: two side-by-side skeletons with no *resolvable* seam mapping — a fresh refit output beside its target body (`mochifitter.md`), an unplaced mergeable. Pre-seam does not mean seamless: a raw refit output does carry a `MergeArmature`, it just has no base to resolve against yet, so what `Check` emits there is the `mergeTarget` abstain and **not** the bare-prop REFUSE (measured). The two route differently — read which string you got before repairing anything. It pairs by **bone name** (the one place the never-reimplements-name-matching rule above does not apply, because there is no mapping to reflect) over the base's humanoid bones only, so `context`/`dropped` are always 0. Everything else is the same implementation: the ≤1 proxy `REFUSE`, the weighted-bone filter, worst-first offenders, `maxOffset`/`maxWithinEps`. Two differences to drive it correctly: **`maxOffsetMm` has no default** — a warp solver's residue is ~0.001mm and pre-seam staging is legitimately millimetre-scale, so the tolerance is the caller's to state and the seam door's ε is two orders of magnitude too loose for a refit; and **ambiguity `REFUSE`s** (a duplicated armature copy under the mergeable, two base bones sharing a name, both roots resolving to one object) rather than scoring an arbitrary match. Its output is labelled `[CheckSeam:bare]` and logs to `checkseam-bare_*` at finer precision — never read a bare RunLog as a seam-scored one, the tolerance regimes differ by orders of magnitude.

`ReportShapeOverlap.Report(string meshObject, string[] shapeNames = null, string outfitRoot = null)` fills the coupling blind spot `CheckSeam`/`CheckAvatar` leave — neither reads blendshapes. Over **one** mesh it emits per-shape
touched-vertex footprints with pairwise **containment** (`|A∩B| / min(|A|,|B|)`) — the locator for the
double-subtraction `outfits.md` warns of, a base `Shrink_*` left worn while an outfit `ShapeChanger` shrinks the **same vertices**, invisible to the render sheet and the fit gates — plus a per-shape **resolution table** (reaction, current weight, resolved-target, and the `MISMATCH` / `CONFLICT` / `UNKNOWN` / `MISSING` cells).

Both arguments are optional because it assembles its own co-active set: caller-passed ∪ worn-nonzero ∪ every MA `ShapeChanger` row under `outfitRoot` resolving to **this** mesh. **The third source is the point of the tool and is gated on `outfitRoot`** — those reactions sit at weight 0 at edit time, exactly what the caller's own scan cannot see — so omitting the root silently narrows the set to the first two; `reacted=0` is the tell.

**A declaration behind a parked ancestor is annotated, not flagged.** MA conditions every reaction on its ancestors' active state, so a row whose every declaration sits under an inactive object may not apply at the initial state: those carry `[inactive: <path>]` and count in `inactiveDeclared=`. Read the named ancestor and rule — it is dead authoring residue, or something that should be live. **`MISMATCH` still means nothing declared the shape at all**, because proving a declaration dead needs MA's build-time animation index (any clip binding that ancestor's `m_IsActive` keeps the reaction live), which no edit-time read has; flagging without it would invent offenders on every FX-toggled wardrobe. Declarations that are toggle-driven, `Inverted`, or accompanied by a live sibling are already excluded from the annotation, and an inactive `outfitRoot` you passed yourself is a note rather than a charge against every row. `nondestructive.md` owns the mechanism.

On a mixed compose there is no single outfit root: pass the **avatar root** as `outfitRoot` so every source's declarations ingest — per-source runs each manufacture `MISMATCH` rows the other root's declarations would have resolved.

A **`Report`, not a verdict** — a deliberately un-asset-tuned containment floor flags pairs as places to look. **`map-outfit-shapes` drives it and owns the disposition doctrine**: what each cell means and how to rule on a row live there, not here. Drift is loud in one direction only — MA absent is a silent no-op, MA installed with the type or member unresolved warns and yields zero reactions.

`RenderAvatar.Capture(target, angles, hide, margin, showGizmos, resolution)` renders **one** avatar subtree in isolation, through the operator's **Scene View**, to a temp contact-sheet PNG with the **NDMF/MA preview resolved** (reactive fit applied). Read-only: restores the view, leaves the scene un-dirtied. Two framing traps — angles are the six **world** axes, so a rotated target shows the scene's front rather than the avatar's; and it renders the avatar **as the operator has it**, so an eye-hidden child is silently absent from the sheet.

Each `hide` entry resolves as a **descendant of the target** — a path relative to it, or an exact child name — and one that resolves to nothing **FAILs the grab** rather than quietly rendering the subtree it named. `CaptureDiff` refuses differently there: it replays frame A's list, where an entry usually stops resolving because the edit under test deleted that object, so its cure is re-grabbing frame A. A resolved entry that excludes no drawable renderer is a note (`hideEmpty=[…]`), not a failure. Two counts ride the summary: `eyeHidden=` (operator eye-hides skipped) and `hideExcluded=` (renderers this call's `hide` dropped).

**Its ceiling is the point.** A model-read of the sheet is **not** an agent gate — not for fit (quantified `CheckSeam` decides that) and not for clipping. It is operator-eye evidence, the visual companion to `verify.md`; what it shows is the editor *preview*, not the baked upload clone (`nondestructive.md`), and headlight shading is truthful for geometry and silhouette, not matcap/rim/fresnel.

**Freshness.** **Grab in a separate call from any edit** — a same-call grab shows the pre-edit proxy — and **one grab per call whenever an NDMF rebuild may be pending**: grabs batched into one call all refuse while the rebuild is in flight, each fine run separately. Two tokens ride the summary. `gate=` reads `armed` (a probe ran and NDMF's settle predicate read clean) or `exempt` (nothing to certify) — that is *probed and settled*, **never a guarantee the pixels are current**. `canary=live` is the one that certifies them: the door nudges a drawn blendshape and requires the pixels to move, so it catches the editor-wide skin-deform freeze (`unity.md` §Sharp edges) that no mechanism-shaped check caught. Absent both, treat **byte-identical pixels around a verified edit as stale**. The door also refuses outright on a pending script reload, and FAILs when the canary is dead rather than shipping a sheet — each refusal names its own cure. A transient settle miss logs a `Warning`, not an `Error` — re-grab. Mechanism, the three freeze states, and residuals: `Tests/Editor/RenderAvatarFreshnessGate.md`. **Grab driven state while still in play** — exiting reverts to authoring state, so a post-exit grab verifies only the static baseline.

**`CaptureDiff(target, against)` — the door that settles decisions.** `against` is a prior grab's PNG; it pins that grab's framing from the `<png>.cam.json` sidecar, then compares B to A **exactly**, per angle — no tunable tolerance, so no threshold to creep against one avatar. Reports counts and bboxes, never a verdict; FAILs loud rather than compare mismatched framing. **Its bbox y grows upward from the bottom edge** (`bboxOrigin=bottom` rides the summary whenever any angle reports one) — read it top-down and a change at the top of the frame localizes to the wrong place, which reads as "no change there". Trap: `_Time`-driven shading (emission scroll, rim, dissolve) advances between grabs into a phantom diff — trust it only for time-static shading. `map-outfit-shapes` argues keep/hide calls from these, so unlike `Capture` its caveats are load-bearing.

## Avatar tools

`com.ryan6vrc.avatar-tools` (from `vrc-unity-tools`, local `file:` ref) is the agent-callable kit for turning a vendor avatar into our own normalized avatar. (The package split is by domain, not read-vs-write: `agent-tools` holds generic Unity inspection/reporting plus the shared conventions; `avatar-tools` holds the avatar-owning kit, including its own read-only reporters like `ReportPackage` — and depends on `agent-tools`, never the reverse.) The kit also carries **standalone clip and material utilities** that are not part of the vendor→owned pipeline — `RepathClips`, `OwnControllerClips`, `RemapMaterials`, and the display packer below. They sit here because clip and material surgery is this package's domain, not because an avatar is being owned; read the declared domain as *avatar assets*, not *avatar owning*. Each tool is a static method invoked via `execute_code`, emits a one-line summary that ends with its JSON RunLog path in-band
(`… => RESULT | log=<path>`, written under `Assets/Agent/RunLogs/`; omitted only when the write
failed), and is **idempotent** (safe to re-run on the same instance). Per the tool-design grammar a `Check` carries a `PASS/FAIL` verdict; a `Report` (e.g. `ReportPackage`) is a verdict-free descriptive digest that ends `=> OK` (or `=> ERROR` only on bad input / a mid-scan exception — never a content verdict). They share `RemapReferencesByPath`, a path-based remapper that rebinds scene references from the vendor hierarchy to ours, duplicate-sibling safe.

Avatar assembly here is non-destructive (NDMF / Modular Avatar / VRCFury); see `nondestructive.md` for the reference-hardening model that governs what these path-based tools can rebind and what they must preserve.

- `ReportPackage.Report(vendorFolder)` — read-only: per-FBX mesh inventory, the face mesh and the FBX it resolved into (`visemeMesh=`, naming its own basis in parens, and `avatarFbx=`), a body **guess**, the superset FBX (or "none"), a constraint count, and two fields that state their own reach rather than claiming coverage. **`bodyGuess=` stays a guess even where the face mesh is a fact**: nothing declares "the body mesh", so it takes the most-blendshapes renderer that is not the face, which on a base whose one body mesh also carries the visemes is something else. `avatarFbxCandidates=` means several FBXes here carry a declared face mesh — check `avatarFbx` is the avatar you are owning. The **constraint count is a name-substring rule** (`"Constraint"` anywhere in the type's short or full name) — which is how it counts Unity's built-ins and VRChat's alike without referencing either assembly, and equally how it counts a vendor's `ConstraintHelper` or `ConstraintSettings`. Read it as an upper bound on constraint-ish components; `ReportGimmick` is the door when the topology matters. **`nonSdkNs=`** is a verbatim `Type.Namespace` census of every non-SDK component, most-present first — namespaces, not framework names, and the tool recognizes none by name: an entry means *a framework is here, go read it*. Components whose script didn't resolve are **counted** (`unresolvedScripts=`), not skipped, because an unresolvable component is exactly the framework a census cannot name — nonzero means the list is incomplete, not that nothing is there. **`toggles=`** reports clip-driven `m_IsActive` membership as a ratio plus its mechanism (`3/14(clip-m_IsActive)`), carries `, caveated` whenever any non-SDK framework or unresolved script is present, and names its own FX reach in the RunLog, saying which of two probes answered. A descriptor FX slot **names the prefab it resolved from** — read that name rather than assuming the first prefab, which may carry no descriptor or an `isDefault` FX layer. Failing that, a controller whose **asset path** contains `_FX`, first in path order — a path match, not a filename convention, so a folder named `*_FX` qualifies every controller beneath it. A controller a framework merge component mounts is read only when its path happens to carry `_FX` that way, so a package whose FX arrives entirely through MA `MergeAnimator` or VRCFury `FullController` from a path without it reports `fx-controller-not-found`, which reads like "no FX here" and is not; `CheckAnimator` resolves those mount points. A framework compiling toggles at build makes `toggles=` carry no removability information at all — read the vendor's own components before fixing a keep-set.
- `MatchHumanoidRig` — builds a fresh humanoid from our own model's skeleton (the bind, so it survives reproportioning) and conforms the vendor's bone mapping + muscle settings onto it (copying a rig wholesale is unreliable). `poseDriftMm` is informational only — a raw max world-space drift of the humanoid bones vs the vendor, in mm; expected nonzero after reproportion, never gates. `Preflight` reports the pre-reimport preconditions go/no-go without reimporting (the reimport is the operation, so there is no `whatIf`).
- `CheckHumanoidRig` — read-only guard: asserts each humanoid bone's stored bind (frozen in the `.meta`) still matches the current model's local position, FAILing (named) on drift — catches a re-export that skipped re-running `MatchHumanoidRig`. Position-only: Unity stores a thumb-corrected bind rotation that legitimately differs even on a healthy rig. Its second door, **`CheckHumanoidRig.InspectAvatar(avatarRoot)`**, is scene-scoped and answers a different question: on a placed avatar it names the **humanoid-vs-skinned divergence** — a humanoid bone mapped to a transform nothing skins (`proxy`, with the nearest same-named skinned transform offered as a *candidate*, never asserted), and a transform elsewhere carrying the plain humanoid label while the mapping points somewhere else (`name-shadow`, the class that makes a by-name bone lookup silently wrong). It exists because a rig's mapping lives **only** in the source model's `ModelImporter.humanDescription`, where every prefab, scene, controller and clip reads consistent with the wrong answer. Verdict grammar is `CheckAvatar`'s — `PASS` / `CLASSIFY` (a finding to route, not a tool failure) / bare `FAIL` on bad input — and its RunLog is labelled `[CheckHumanoidRig:avatar]` on its own filename stem, so an avatar-scoped record can never be read as a bind-drift one. **"Skinned" is decided by bone instance *or* bone name, and the name arm is a declared heuristic**: pre-bake a mergeable's renderers skin the mergeable's own armature copy, which the build zips onto the base's same-named bone, so an instance-only test reads an ordinary composed avatar as almost entirely proxied — the same pre-bake fact `ReportGimmick`'s `chain subtree` cell carries above. The emitted scope note says so and routes a genuinely ambiguous row to a bake.
- `ConformRenderers` — assigns vendor materials by renderer name from any source hierarchy (by reference, no `.mat` copies; an optional `ownedToSource` override map covers meshes renamed during normalization, its direction the reverse of the transplant kit's — see below) and applies the renderer-normalization standard below. `whatIf` previews the full match/verdict and mutates nothing. A **mergeable** (no humanoid rig / no `Hips`) **PASSes with a note** on the missing anchor rather than FAILing — that missing `Hips` is exactly the input `own-mergeable` prescribes it for; an avatar base still resolves its anchor via `Hips`. It **FAILs on a slot still bound to Unity's built-in `Default-Material`** — run it after materials are remapped.
- `CopyDescriptor` — gates on scale + face-blendshape parity, transplants the VRCAvatarDescriptor with refs remapped, and installs a **fresh PipelineManager** (never the vendor blueprint ID). Post-copy it recomputes `ViewPosition` via `FixViewpoint` (non-fatal — a viewpoint miss never flips the transplant verdict). `whatIf` runs the gates + critical-ref snapshot and reports the predicted outcome (remap counts land only on execute).
- `FixViewpoint(ownedRoot, referenceRoot, whatIf=false)` — recomputes the owned descriptor's `ViewPosition` from a **required** known-good `referenceRoot` (vendor source, or the pre-reshape prior version) plus both rigs' Head + eyes, re-seating the creator's eye→viewpoint offset on the moved eyes rather than snapping to them. **Named FAIL (no guess)** on a non-humanoid rig, unmapped eyes, or coincident eyes. Idempotent. The `reproportion` skill drives the in-place case; `CopyDescriptor` calls it post-copy.

The **component-transplant kit** — `CopyComponents`, `MoveComponents`, `GraftHierarchy` over a shared transplant core — is **component-agnostic**: selection is a list of **type-name strings** (resolved via `TypeCache`, matched by assignability, fail-loud on ambiguity), so the same tools serve VRC dynamics on a base body and MA/VRCFury/NDMF on an outfit without the package referencing those assemblies (stays VRC-SDK-only). Two tiers: a **deep** tier for the closed, owned VRC set (physbone / collider / contact / VRC-constraint — dependency-follow, `Col_*` leaf-anchor recreate, hard/soft criticality, `force`/scaffold, from a typed table) and a **conservative** tier for everything else (MA / VRCFury / NDMF / unknown / Unity built-in constraints — `CopySerialized` + generic object-ref remap, leave-missing-missing). The **reach root** `(vendorSource, ownedRoot)` bounds the remap: refs to objects under the vendor source rebind to our counterparts; out-of-reach refs (assets, other-avatar objects) are left for placement-repair.

A **differently-named armature-root GO** (owned `Armature.1` vs vendor `Armature`) nulls every ref through it under the name-based matching above. `CopyComponents` / `GraftHierarchy` take an optional `vendorToOwned` map (injective, **case-sensitive**) that reconciles it — one entry (`"Armature" ⇒ "Armature.1"`) covers hosts and relocated-outside-armature anchor refs alike. An absent map is a no-op; a non-injective or ambiguous map (one that can't address a unique dest sibling) is a **named FAIL in both `whatIf` and execute**, never a silent mis-bind.

**The remap moves the OBJECT half of an MA scene ref, never the `referencePath` string** — out of scope in every transplant tool, deliberately. It usually costs nothing: hosts land at the same indexed path, so an avatar-relative path stays correct, and a ref carrying both halves resolves off the live `targetObject` first — **but only while that target lands under the avatar root** (`nondestructive.md` §Reference hardening), which is what makes the second shape below bite rather than self-heal. It bites where the destination path genuinely differs — a `vendorToOwned` segment rename, or a reach root that is not the avatar root on either side — and then only for a path-only ref, which is the shape that doc tells you to author. Repathing here would mean guessing an avatar frame the tool does not have, the prescribed copy source being a standalone vendor prefab with no descriptor; **run `CheckAvatar` after either shape instead — its `MA-scene-ref` class names a path that resolves nowhere from the new mount.**

**Rename-map direction — the kit runs two, pointing opposite ways.** A rename map's **key** names the hierarchy its tool **walks**; its **value** the hierarchy that tool **resolves into**. Direction follows traversal and is not a style choice, a dictionary being unindexable by its values. So the transplant tools (walking vendor, resolving into ours) take `vendorToOwned`, while `ConformRenderers` (walking our renderers, resolving into the source) takes `ownedToSource` — and holding "one map" across both gets one backwards. Two consequences follow: `vendorToOwned` **must be injective** to address a unique dest sibling (enforced), where `ownedToSource` is legitimately **many-to-one** (two owned meshes taking one source renderer's materials — inverting it would make that inexpressible); and `vendorToOwned` matches **Ordinal** where `ownedToSource` matches **case-insensitively**. Trust the parameter names over the shape of your map.

- `CopyComponents(ownedRoot, vendorSource, typeNames, force=null, vendorToOwned=null, whatIf=false)` — reproduce all components of the named types onto our rig, **additive + idempotent** (count-parity skip per `(host, type)`; never destroys; a re-run is a no-op). `whatIf` reports the full plan and mutates nothing; a real run replays that same plan (preview == execute). A **flagged-missing host is PASS** — the named prune-backstop list to triage (`force` it via `vendorRelativePath :: ComponentType`, re-prune, or accept). A **null ref on a copied component** is surfaced separately as "verify — may block build" (non-fatal but can abort the downstream VRCF/SDK build). **FAIL** only on a vendor-source leak, `AddComponent`/scaffold failure, or unresolved type. Copy from the **standalone** vendor source, not an outfit already placed in an avatar. Flagged-missing hosts are classified in the RunLog note: **`[bone]`** — a skeleton bone absent on our rig, a genuine prune/rename divergence to investigate; **`[holder]`** — a non-bone GO the source parked the component on (deep-tier only; conservative hosts are untagged, having no scaffold path). When the source parked dynamics on holder GOs (a consolidated/grouped avatar), the holder paths are absent on a **faithfully re-exported** target and flag `[holder]` — physbones/constraints always, and colliders/contacts too **when their holder's parent is also absent** (holders under an `AvatarDynamics/…` container). A collider/contact whose holder sits directly under a **surviving bone** is instead auto-recreated (`RecreateLeaf`, no force key needed) and never appears in the `[holder]` set. Forcing the `[holder]` keys scaffolds those holders back — anchors path-remap to our bones, collider refs resolve by topo order — which **reconstructs the grouping, so a following `MoveComponents` is redundant**. Force-all-`[holder]` is safe **only** when the target is a faithful re-export (no bones pruned, no content dropped — the reproportion twin/copy case); on the vendor→owned path a `[holder]` may be a deliberately-pruned accessory, so the flagged-missing default (force / re-prune / accept) stands.
- `MoveComponents(ownedRoot, targetRoot, typeNames, destPath, whatIf=false)` — relocation primitive (the type-name list replaces the old `mode`). Matches components whose effective anchor descends from `targetRoot`, mints a holder under `destPath`, pins each anchor to its original transform, and rewires inbound serialized refs to each re-created component (a physbone's `colliders[]` entry to a relocated collider; `inboundRefsRewired`, whatIf-predicted) — behavior-neutral, **never moves a bone**. Matching is by **anchor, not current location**: a later call with a broader `targetRoot` re-captures components an earlier narrower call already grouped, leaving stale empty holders — order the calls broad→narrow. Anchor field per type comes from the VRC table; a targeted type with **no table anchor FAILs loud** (refuses MA/VRCF/NDMF *and* Unity built-in constraints). Idempotent (skips a holder already placed under `destPath`); run **pre-prefab**. Called N times at operator discretion; echoes matches for closed-accounting.
- `GraftHierarchy(ownedRoot, vendorSource, subtreeRoots, vendorToOwned=null, whatIf=false)` — copies named GO **subtrees wholesale**: scaffold the full structure (vendor verbatim local TRS) + copy **all** components on every GO (type-blind), remapped against the reach root. For pulling an outfit's authoring/menu subtree without listing every GameObject. Inverted contract vs CopyComponents: a missing host is **expected/normal** (you are scaffolding), never flagged. Count-parity + reuse-by-path idempotent.

The **controller owning/consolidation kit and the compile/decompile substrate** — `CleanController`, the clip-repathing pair (`RepathClips`/`OwnControllerClips`), `CompileController`/ `DecompileController`, and the `SchemaValidation`↔`ControllerRules` split — are `avatar-tools` members obeying the same static-method + `whatIf` + RunLog conventions as the tools above. Their contracts, the `Decompile→Compile` round-trip that reframes the owning tools, and the YAML authoring language are in `docs/animator.md` (schema: `docs/animator-schema.md`).

Two standalone **scene utilities** round out the kit, simple enough that the signature is the contract (open the tool): `RemapMaterials` — swap materials by **asset path** across a hierarchy, in place (no source hierarchy, no name matching — a different operation from `ConformRenderers`' copy-by-renderer-name); `ConstrainedDuplicate` — clone a hierarchy and wire VRC constraints between original and duplicate bones.

The **`own-base` skill** (in `vrc-skills`) orchestrates these — it holds the judgment, gates, and sequencing; the tools hold the mechanics. In a transplant diagnostic, read what each count *means*: a **flagged-missing host is PASS** (expected subset — triage the named list), while a **vendor-source leak** or a **null ref on a copied component** stays stop-and-investigate (almost always a name/path mismatch).

**Renderer-normalization standard:** every renderer's bounds are **ensured ≥** an origin-centred anti-cull floor (the box `ConformRenderers` declares) — grown to it, never shrunk, so a deliberately larger box survives and the warning names the extents it kept — the Anchor Override is set to **Hips** only when invalid (null or not a child of `ownedRoot`); a valid internal anchor is preserved, and a null Root Bone is filled with Hips. Not copied from the vendor (creators get these wrong). On a *composed* avatar, Modular Avatar `Mesh Settings` can own bounds/anchor at build — there the tool's writes are authoring-only, so its PASS is not a runtime guarantee.

`OwnMaterial(materialPath, outDir=null, forkTextureSlots=null, newName=null, force=false, whatIf=false)` brings a vendor material into ownership and forks the **named** texture slots into the owned copy's own namespace — every unforked slot keeps its source-GUID reference, and the `slots[]` provenance table it returns is the caller's gate. Routing is target-identity: `outDir` given ⇒ own a vendor source (or branch an owned one) into a NEW `.mat` (named `newName`, default the source's name); `outDir` omitted ⇒ augment the already-owned source in place (fork more slots). A locked-Poiyomi copy is unlocked via Thry's ShaderOptimizer — it **refuses** rather than risk Thry's blocking dialog when the original-shader tag can't resolve, and leaves the vendor source untouched. The `own-material` skill holds the judgment of which slots to fork; the tool executes it deterministically and returns a one-line PASS/FAIL + RunLog path.

## Thumbnails

`RenderThumbnail` (edit mode, the default) and `RenderThumbnailPlay` (play mode) are two front-ends over one camera/capture spine (`RenderThumbnailCore`) — same caller vocabulary, a 1200×900 `png=` that feeds `UploadAvatar`. Edit mode is one synchronous baked call. Reach for play mode only when dynamics or FX must be truthful: it renders with hair/cloth **settled** by the real physbone solver and FX toggles/materials **resolved**.

Both front-ends write a RunLog **on a clean success** — play mode one per session verb (`Begin`, the `Shoot` *completion* verdict, `End`), so the sweep's which-doors-were-driven signal sees these arcs and `End`'s restore claim has an artifact behind it rather than only its own return string. `Status` writes nothing (a poll, not an event), and neither do the refusal and exception paths, so a RunLog's *absence* does not mean a door went undriven.

Play is a **session**, not a call (physbones need the player loop, and the tool can't flip play itself): `Begin(target)` → `manage_editor play` → `Shoot(...)` (async — returns a tag, poll `Status()`) → `manage_editor stop` → `End()`. One `Begin` serves many `Shoot`s. Toggle/menu-param state set in play survives a `Shoot` (the swapped-in FX playable is seeded from the outgoing one; the toggled states re-resolve during settle) — but layer state a param does not imply, e.g. trigger-latched, does not. Settle is never asserted — the verdict **names any chain still moving** at capture, so an `OK` shipping alongside a populated `moving=[…]` is rendered-but-not-settled and the shot is not the settled one you asked for. The venue is a loaded scene lit by its own lights (not edit mode's fixed rig); `End` reopens it from disk, discarding the pose and emulator edits. The `shoot-thumbnail` skill picks the mode; play-mode capture mechanics are split: the graph-wins evidence rule is `verify.md`'s, local-layer cull and param drive are `emulator.md`'s.

## Publish

`UploadAvatar` batch-uploads composed avatars live to VRChat, driving Continuous Avatar Uploader (CAU) by reflection (CAU absent ⇒ **REFUSE** with the fix). **Operator-gated** — the `upload-avatar` skill's explicit "upload now" is the only trigger, never autonomous — and fail-loud: verdicts are **PASS / REFUSE / FAIL**, where REFUSE means the environment isn't ready (CAU absent, not logged in, panel closed, wrong build target) and FAIL is a genuine upload rejection. The not-logged-in case self-heals: the door kicks CAU's saved-credential restore itself, so that REFUSE normally costs one re-run rather than an escalation — the operator's interactive sign-in is the only login the door can't reach. It runs async — `Run` fires and returns while the editor update loop pumps CAU's continuations, so poll `Status()` until it stops reporting "running". A per-handle attempt ceiling counts *consecutive* failures (cleared on each success) so account safety doesn't lean on skill prose, and **no blueprint id ever enters output** (public-repo safety). `whatIf` previews readiness without uploading.

**An upload cannot rename.** CAU sends a name exactly once, on the new-avatar path; an update's record carries the *live* name, re-fetched immediately before the bundle write, so anything staged is discarded. Two consequences that bite silently: a GameObject rename never reaches an uploaded avatar's display name, and a re-upload republishes under the **old** name with no warning. The scene is therefore not evidence about what is published — `ReportAvatarRecord` is, reading the live blueprint record as the server holds it.

`UpdateAvatarRecord` is the door that can change a live record: name, description and tags, metadata only. Every field is **null-means-unchanged**, which makes an empty tag array the only way to say "clear the tags" — and a call that sets nothing refuses rather than posting the record back unchanged, since that would bump the server's version and report success for an edit that never happened.

The call hands the API a whole record, and the reason that is safe is worth stating precisely, because the obvious reading is wrong. The bundle and thumbnail survive because the SDK **never submits them** — it narrows the record to a changes payload internally — not because the server tolerates a full post. Description, tags, release status and styles *are* submitted, round-tripped from the read. So the guarantee is "the fields you didn't set are written back as they were", not "untouched": a concurrent writer between the read and the write gets reverted, and the sibling calls that take the same record (`UpdateAvatarImage`, `UpdateAvatarBundle`) genuinely do write the heavy parts. This door does what the SDK's own control panel and CAU do, and inherits exactly their safety envelope.

It requires `expectCurrentName` and refuses on mismatch, chained from `ReportAvatarRecord`'s reported name, because the write targets whatever `blueprintId` the `PipelineManager` holds — an id the caller never sees — and a stale one would land the edit on a different published avatar. Treat it as a **best-effort confirmation, not a compare-and-swap**: the read and the write are separate requests with no server-side conditional, so a name that changes in between is not caught, and a display name is not an identity, so a stale id pointing at an identically-named record still passes. It narrows the blast radius; it does not close it.

Retyping that name rather than chaining it will usually refuse, because **VRChat sanitizes submitted text server-side**: an ASCII period comes back as U+2024 ONE DOT LEADER, and the two are visually identical. This is not name-specific — descriptions and the API's own error strings arrive sanitized the same way — so match any published value against the *landed* form only. Every value these doors report is the landed string, and a substitution is reported as the code-point positions that changed.

Two things are deliberately absent, and should stay that way rather than being read as gaps. `ReleaseStatus` is not settable: it is the field that makes an avatar public, and folding an irreversible visibility change into a general metadata setter is how it gets flipped by a caller who was only fixing a typo. `DeleteAvatar` sits one method away in the same API and is not built at all. A door earns a destructive verb explicitly or not at all.

Two traps for anything else built on `VRC.SDKBase.Editor.Api.VRCApi`, both cheap to get wrong: it carries its **own** auth, so `APIUser.IsLoggedIn` can read `False` while reads and writes succeed — gate a `VRCApi` door on it, as `UploadAvatar` legitimately does for CAU, and you refuse a working environment. And `ApiErrorException.Message` is the content-free default string; the status and the server's real text live in its `StatusCode` and `ErrorMessage` **fields**. A 404 there means "no such record **or** not visible to this account" — the API does not distinguish them, so neither should a diagnostic.
