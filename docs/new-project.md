# Adding a Unity project to the workspace

Ordered procedure for standing up a **new** Unity working venue under an already-working workspace. A Unity project is a working folder untracked by the workspace repo, carrying a local-only git repo of its own (CLAUDE.md §Layout); step 1 stands that repo up, and no later step touches git. From-zero bring-up of the workspace itself (installs, MCP wiring, package restore) is `bootstrap.md`. Folder conventions live in [`LAYOUT.md`](LAYOUT.md); the Unity pin lives in [`unity.md`](unity.md), package reproducibility in [`../CLAUDE.md`](../CLAUDE.md) §Layout — this doc links, not restates.

1. **Seed the project folder.** Clone the `AvatarProject` sample skeleton (README §Repos) as the starting point, or copy an existing venue, then **remove the `.git`** — the venue is a working folder, not a repo. Add the folder to the meta-repo's **local** ignore, `.git/info/exclude`, so the meta-repo never surfaces it (project names stay out of the public `.gitignore`). **That line also hides the venue from every workspace-rooted `Grep` — ripgrep honors `.git/info/exclude` — so re-include it in an untracked `.rgignore` at the workspace root (`!/<venue>/`), and add `/.rgignore` to `.git/info/exclude` as well.** The tracked root `.ignore` cannot carry that line, because `CLAUDE.md` §Layout forbids naming a personal venue in tracked code; `.rgignore` outranks `.ignore`, `.gitignore` and `.git/info/exclude` alike, and being untracked it names the venue nowhere public. Skip it and the venue is not merely partly blind but wholly absent — a workspace-wide sweep returns zero hits from it and says nothing about the omission, whatever the venue's own `.ignore` gets right. **Stand up the venue's own git repo and its `.ignore` together, in that order.** They are one decision: the `.gitignore` is an allowlist, so on its own it would reduce every `Grep` in the venue to the tracked set, and the `.ignore` is what cancels that. Write the `.ignore` first and the collapse never happens; the collapse lands the moment the allowlist file is written, not when `git init` runs. Copy both from an existing venue rather than composing them fresh. Then `git init -b main`, and before the first commit confirm the allowlist held: `git ls-files -o --exclude-standard` must list nothing outside the re-included patterns and nothing under a denied tree — a count is not the check, because every file a mis-ordered rule leaks has an allowed extension.

The `.ignore` also carries the venue's pruning, which is not optional and does not depend on the repo: ripgrep, which the `Grep` tool wraps, honors a `.gitignore` only where it finds a `.git` in an *ancestor* directory, so a venue inside the workspace folder inherits that by accident of location and one placed elsewhere gets nothing, silently. `.ignore` is honored unconditionally and is invisible to git. Without its prunes a `Grep` scoped to a venue walks the ~25k-file `Library/` (`PackageCache` lives inside it): measured 40 s, past the tool's own timeout, against 0.3 s with the file present. `rg -uu` is the override for the rare search that does want those trees. Close this step with the `venue-ignore-audit` skill, which measures what the finished pair hides rather than trusting either file to read correctly.
2. **Seed the Agent-I/O tree** the tooling assumes — `Assets/Agent/` with `Snapshots/` (durable) and `RunLogs/`+`Scratch/` (disposable). Create the folders so the first `Check*`/tool write lands cleanly. See [`LAYOUT.md`](LAYOUT.md) for the why.
3. **Set up packages / VPM** per CLAUDE.md §Layout (`vpm-manifest.json` is the source of truth, SDK payloads reproduced from it); `vrc-get resolve -p <ProjectDir>` restores; add anything beyond the floor deliberately via ALCOM, not in bulk. VPM mechanics: `bootstrap.md`. If the avatar skills will run here, the hard floor — copy from `AvatarProject`'s manifests and trim the rest — is the Avatars SDK + Modular Avatar (NDMF rides along) + VRCFury + av3emulator in `vpm-manifest.json`, plus the `com.ryan6vrc.*` `file:` refs in `Packages/manifest.json`; everything else there is convenience, and vendor assets bring their own shader needs (lilToon/Poiyomi). One sanctioned divergence from that reproducibility: a **no-registry, VPM-shaped vendor package** may be embedded directly under `Packages/` — it lives outside `vpm-manifest.json`, so it reproduces by manual re-extract from the asset library, not `vrc-get resolve`; leave a note beside the manifest so a restore doesn't silently drop it.
4. **Wire this Editor for the agent** (if one will drive it) — install the in-Editor MCP package and Roslyn so `execute_code` gets modern C#; both are per-Editor (mechanics + the mark-Editor-only Roslyn gotcha: `bootstrap.md`). **Do not add a `.mcp.json` server for the project.** The workspace's one `UnityMCP` server reaches every local Editor; sessions route explicitly (`set_active_instance`, full `Name@hash` — `unity.md`). A per-project server name is a false promise — any server can connect to any instance — and each extra server duplicates the whole tool surface and its deny list. A separate server is earned only by a different trust posture, not a different project. `run_tests` needs no per-project action (the proxy allowlist already hides it — `bootstrap.md`; venue rule: `verify.md`). **Set the project for an unattended Editor:** `ProjectSettings/ProjectSettings.asset` `runInBackground: 1` — without it play mode renders no frame while the Editor is unfocused: `EditorApplication.update` keeps firing, `Time.frameCount` sits still, VRC constraints (once per rendered frame) never solve, and a recorder logs a flat rest with no error. The per-machine Editor preferences that pair with it are `bootstrap.md` §3.

A new **tool** sub-repo (a `vrc-*` package) is a different thing entirely: its own git repo, added to the bootstrap clone list and the meta-repo ignore, versioned normally. That's not this runbook.
